## 0. 2026-11-23 서면의 명시적 금지·수집 조건 및 대면 가공 설명의 운영 해석

**근거:** [2026-11-23 정보처 서면 회신 원문(수정 없는 전문)](sources/2026-11-23-hufs-information-office-reply.txt) 및 [운영자 대면 설명·가공 방침과 긴급 철회 기록](public-data-operating-decision.md). 운영자는 **정보처 직원 두 명에게서 공개자료의 활용·가공이 가능하고 학교 서버에 부담을 주지 않으며 비공식임을 표시하라는 설명**을 대면으로 들었다고 전했습니다. 학교는 별도 과거 학기 파일·목록·API를 제공하지 않으며 서비스를 승인·인증·제휴하지 않았습니다. 운영 방침은 **서면에 명시된 금지사항은 금지, 자동 수집은 서면 수치/기간 그대로, 그 밖의 로그인 없는 공개자료 검색·가공·비복제 분석은 대면 설명을 참고해 운영자 책임으로 진행**하는 것입니다. 다만 서면 말미의 '**위에 적지 않은 이용은 허용하지 않습니다**' 조항과 이 해석은 충돌할 수 있습니다. 이는 학교의 공식적인 포괄 허가 확인이 아니며 철회·중단 요구에 즉시 대응합니다. 추가 문의는 당분간 하지 않습니다.

| 구분 | 현재 적용할 경계 |
|---|---|
| **서비스 표시·디자인** | 모든 주요 화면에 “본 서비스는 한국외국어대학교의 공식 서비스가 아니며, 정확한 정보는 학교 원문을 확인하시기 바랍니다” 수준의 **눈에 띄는 비공식 고지**. 학교 로고·엠블럼 및 공식처럼 오인되는 이름·디자인 금지. “학교 승인”, “학교와 협의”, 공식 인정·보증 표현 금지. 모의신청 화면도 실제 수강신청 시스템과 구별 |

| **강의 개설 이력·전망** | 대면 공개정보 가공 설명을 기준으로 공개 개설 이력·과목 메타데이터의 검색/추세를 개발·필드별 검수 대상으로 포함. **교수명·'수강 관련 정보'는 서면 금지대로 제외**. 금지 표현과 충돌할 소지가 있는 개별 분반·정원·수강 항목은 위험 기록/검수 전 공개 보류. 학교 공식 개설/수강 판정으로 오인 금지 |

**두 안내의 권한·유효성:** 운영자 추가 설명에 따르면 이메일과 대면 안내 **모두 정보처 직원 차원의 응답이며, 학교 기관의 확정된 공식 이용 정책이 아닙니다.** 학교 도메인 이메일이 있다고 학교 차원의 영구 허가·기관 승인으로 해석하지 않습니다. **자료 항목과 수집 가능 범위는 향후 확대될 수도 축소될 수도** 있습니다. 그러나 확인된 새 기준이 나오기 전까지 한모는 현행 서면의 구체 금지/수집 제한을 자체 기본 운영 경계로 지킵니다. 변경 근거·필드별 재심사·긴급 중단/재개를 [잠정 정책 ADR §1.1](public-data-operating-decision.md)에 기록합니다. 2026-11-23 정책은 고정 불변인 학교 공식 규칙이 아닙니다.

### 0.1 자동 수집 계약 · 위반 시 실패 폐쇄

- 대상은 **로그인 없이 공개된 화면에 노출된 주소**만. 학사시스템 내부 주소·화면에 나타나지 않는 엔드포인트·보호 페이지/우회 경로 호출 금지.
- **학사공지:** 1일 1회 이하. **첫 목록 페이지만** 조회하고, **새로 올라온 공지의 상세 페이지만** 확인.
- **강의시간표:** 학기당 2회 이하. 이 한도는 별도 파일/API 제공 허락이나 상세 수강 정보 재배포 허락이 아님.
- 모든 요청 **간격 최소 10초**, **동시 접속 1개**, **1회 실행당 최대 50건**. 여러 작업자·러너가 있어도 전역 실행 잠금/횟수 장부로 합산 강제하고, 수동 실행이나 배포 재시작으로 초기화·우회하지 않음.
- **수강신청·수강정정 기간 및 각 기간의 시작 전 1일·종료 후 1일 전면 수집 금지**. 학사일정의 정확한 금지 구간을 확인하지 못하면 실행하지 않음. 특히 수강신청 기간에는 절대 자동 수집하지 않음.

**2026 동계 계절학기 신청 차단 일정(운영자 제공, 2026-11-23):** 날짜·시간은 `Asia/Seoul` 기준입니다.

| 사용자 전달 신청기간 | 신청 접수 시간 | 정보처 서면에 따라 자동 확장한 **전일 수집 금지** |
|---|---|---|
| **2026-11-25 ~ 2026-11-27** | 매일 **10:00~16:00** | **2026-11-24 00:00 ~ 2026-11-29 00:00 미만** (11/24~11/28 날짜 전체) |
| **2026-12-01 ~ 2026-12-03** | 매일 **10:00~16:00** | **2026-11-30 00:00 ~ 2026-12-05 00:00 미만** (11/30~12/04 날짜 전체) |

단지 10:00~16:00만 막지 않습니다. 해당 신청일 전체와 시작 전·종료 후 각 하루도 수집 금지입니다. 11/29처럼 위 구간 외의 날도 **다른 수강신청·정정 일정 전체가 공식 확인되지 않았으므로 자동 수집 가능일로 간주하지 않습니다.** 이 일정은 사용자가 전달한 2026년 정보로, **학교의 모든 신청/정정 일정이 검증됐다는 증거가 아닙니다.**

- [`data/collection-blackouts.json`](../data/collection-blackouts.json): 날짜·매일 10~16시·KST·전후 1일과 `partial` 검증 상태를 보관하는 단일 정의.
- [`scripts/collection-window.mjs`](../scripts/collection-window.mjs): KST 달력 날짜를 기준으로 앞뒤 1일을 자동 확장하고, 신청일·여유일의 00~24시 내내 차단. 다른 일정 미검증·연결 OFF·수집기 예산 미구현은 **실행 불허**로 처리.
- `npm run collection:status -- --at 2026-11-25T11:00:00+09:00`은 외부 요청 없이 조회만 함. `npm run collection:gate`는 **실제 시스템 시각으로 판정**해 차단이면 비정상 종료하며 테스트용 임의 시각 인자를 허용하지 않음.
- 지금은 실제 HTTP 크롤러/스케줄러가 **없고 `mode: disabled`**입니다. 학교 자료를 가져오는 동작은 추가하지 않으며, 향후 수집기 진입/개별 요청 전 이 게이트 및 #66의 전역 요청 예산·오류 차단을 연결하고 **전체 일정의 공식 검증·독립 운영 인수 전에는 활성화하지 않습니다.**

- **오류 응답이나 접속 제한이 한 번이라도 발생하면 즉시 중단하고 그날 재시도 금지**. 지수 백오프·자동 복구 재시도·우회 IP·대체 크롤러 등으로 계속 요청하지 않음.
- User-Agent에는 **한모 서비스명과 운영자 연락처**를 기재. 사용자별 요청·배치와 무관하게 서버 부하가 예상되면 즉시 중단. 차단은 사전 통보 없이 가능.
- 수집 기능은 **초기 OFF**, 네트워크 접근 전 허용 출처 목록·전역 속도 제한·요청 예산·실행/학기 카운터·금지 날짜·오류 차단·긴급 정지 스위치를 테스트하며, 학교가 조건을 변경·철회하면 즉시 수집/공개를 중단함. 실제 크롤러는 아직 승인된 구현이나 실행 상태가 아님.

### 0.2 금지 기능·기존 구현·배포 차단

**웹 1차 정리 반영:** 졸업 준비 `html/academic-progress.html`과 학사 FAQ `html/academic-faq.html`, 전용 CSS·FAQ JS, 학교 로고 `img/hufs_logo.png`는 [웹 정리 커밋](https://github.com/ot4562-glitch/Hanmo_develop/commit/2712bd939502a31755fd21026ac96fe81650c552)에서 삭제했습니다. 메뉴·사이트맵·빌드·테스트도 수정했습니다. **학교 학칙/졸업요건·FAQ 계산 및 근거형 답변의 순수 코어와 옛 데이터 소스 계약은 코드에 남을 수 있지만 운영 기능은 아닙니다.** 학교 자료 연결 `mode: disabled`를 유지하고 웹 디자인·접근성/실기기 검수는 별도 완료 게이트입니다.

학교 문양을 사용하던 기존 홈·상단바·이미지·파비콘·SVG·메타정보와 실제 수강신청을 연상시키는 화면은 **별도 수정 및 브라우저 QA 대상**입니다. 기존 UI 동결 정책은 새 서면 금지사항을 보존할 근거가 아니므로 관련 변경을 우선하되, 원본 동작·실기기 회귀·디자인 구별을 확인합니다. **2026-11-23 웹 1차 정리로 금지된 페이지·학교 로고 파일 제거와 비공식 고지를 반영했습니다. 그러나 디자인 전수/Windows 실기기 QA, 원본 운영 도메인 공개·학교의 서비스 인정은 완료되지 않았습니다.** `data/academic-source-config.json`의 `mode: disabled`를 유지하고, 금지된 필드가 포함된 기존 Supabase Draft #93·공개 payload는 수정·재설계 전 활성화하지 않습니다.

### 0.3 운영자 최종 해석(2026-11-23) · 공개자료 가공 이용과 즉시 철회

**데이터 항목에 관한 대면 안내 재확인:** 운영자가 전한 정보처 직원 두 명의 설명은 공개자료의 단순 열람뿐 아니라 **검색·분류·집계·분석·가공도 가능한 취지**였습니다. 운영자는 **서면에서 구체적으로 금지된 항목을 제외한 공개자료 활용은 대면 안내로 판단**, 자동 수집 조건은 **서면에 적힌 제한을 전부 그대로 준수**하기로 했습니다. 이전의 '합성 데이터 기능 개발만 허용하고 모든 추가 공개정보 이용은 서면 재확인 전 보류'라는 지나치게 좁은 운영 결정을 이 기준으로 수정합니다. 추가 학교 문의는 당분간 진행하지 않습니다.

이에 따라 **PC 웹 기능 자체의 차별화**를 위해 학사공지 정밀 검색, 과거 공개 개설 관측의 추세·학기별 비교, 공식 공개 일정/행사 메타데이터의 후순위 달력 표시, 공식 문의처 검색/경로 비교를 목표로 합니다. **우선 개발할 학생 기능은 공지 메타 정밀검색·필터·오타 교정·공식 원문 이동**입니다. ‘바뀐 공지만 보기’ 전용 필터와 정정 전후 비교 화면은 학생 효용이 낮아 **개발 목표에서 제외**합니다. 달력은 월간 보기/공식 일정 링크를 유지하고, 검수된 날짜 표시는 #127에서 후순위 선택 확장으로 다룹니다. [최소 데이터 운영 계획](focused-public-data-plan.md)의 수집·검수·비용 안전 상한은 유지합니다. 개설 전망·문의처는 독립된 후속 기능입니다. 개인 메모나 알림을 차별화의 중심에 두지 않습니다. 개별 데이터는 **명시 금지 여부, '수강 관련 정보' 등 표현의 충돌 여부, 원문/가공 구분, 개인정보·권리, 관측 누락, 출처 수정 및 공개 철회 가능성**을 기록하여 검수합니다. 명시적으로 금지된 교수명·수강 관련 정보와 학칙/FAQ·학교 로그인은 사용하지 않습니다.

**주의:** 서면의 '위에 적지 않은 이용은 허용하지 않습니다'라는 포괄 문구가 여전히 존재하므로 대면 설명에 근거한 추가 가공 범위는 **운영자의 해석·위험 수용이지 학교의 공식 확대 허가로 확인된 것이 아닙니다**. 학교 요청/정책 변경·오류 시 수집과 데이터 노출을 즉시 중단하고 정적 번들/DB/캐시/이전 배포본까지 철회합니다. 구체적인 근거·필드별 판단표·절차는 [공개자료 운영 결정](public-data-operating-decision.md), 구현/검증 과제는 [#41](https://github.com/ot4562-glitch/Hanmo_develop/issues/41)·[#66](https://github.com/ot4562-glitch/Hanmo_develop/issues/66)·[#126](https://github.com/ot4562-glitch/Hanmo_develop/issues/126)을 참조합니다. **현재는 데이터 연동 `mode: disabled`, 크롤러/통합 킬 스위치 미구현**입니다.

### 0.4 데이터 범위 양방향 변경을 고려한 데이터·배포 아키텍처(목표)

- **정책 원장:** 각 안내에 `sourceKind`(직원 서면·운영자 전달 대면·확인된 기관 정책), 확인일·적용 판본·공식성 확인 여부·데이터 필드별 사용 판단과 변경 이력을 연결합니다. **현 상태는 직원 안내 기반 잠정 정책**입니다. 향후 학교 전체 정책을 새로 확인하면 다른 증거 등급으로 기록합니다.

- **확대 경로(별도 검수):** 새로운 근거를 확인한 뒤 `scopePolicyVersion`을 갱신하고 필드별 금지·개인정보·학교 공식 오인·출처/정정·수집 예산을 재검수해 새로운 DTO/스냅샷 후보를 승인합니다. **예전 잠정 안내의 존재만으로 자동 확대하지 않고**, 제한된 수집 횟수를 우회하지 않습니다.

### 3.1 실행·권리·개인정보 경계

- **정적 우선·코드 언어:** 새로운 코드·테스트는 JavaScript + JSDoc을 사용하고, 기존 JS 소스·모의신청 연습은 합성 상태에서 독립 동작합니다. 운영 Supabase 없이도 모의신청·로컬 내정보 선택 기능이 작동해야 합니다. 학점 산술 화면은 삭제됐으며 별도 범위 결정 없이 복원하지 않습니다.
- **학사자료 계약:** 모든 데이터 객체에 이용 근거 범위, 원문 URL, 확인시각, 제외 필드, 집계 방식, 권리/철회 상태를 별도 기록합니다. URL/해시/검수자가 있다는 것만으로 금지 자료 사용이 허용되지 않습니다.
- **필드별 구분:** 교수명·서면에서 제외한 '수강 관련 정보'는 사용하지 않습니다. 공개 **과목명·학수번호·학기/캠퍼스별 개설 관측**은 대면 안내에 따른 가공 대상 후보로 검수할 수 있지만, '수강 관련 정보' 금지에 저촉되는 개별 분반·정원·신청 상세는 무조건 허용하지 않고 위험 분류·독립 검수 전 학생 노출을 보류합니다. 학생의 개인 수강정보나 저장된 WIS HTML/CSV는 우회 반입하지 않습니다.
- **계정·개인자료:** 학교 계정/암호/SSO·대리 로그인·학교 학적·개인 성적표·성적/이수 원장 파일을 취급하지 않습니다. 현재 존재하는 직접 입력 프로필 값은 브라우저 안에만 두고 GitHub·Supabase·로그·분석 도구로 보내지 않습니다. 학점 산술 UI는 미제공이며 학교 성적·이수 원장 파일을 취급하지 않습니다.
- **학교 확인 경로:** 공지 및 허용 공개 자료의 공식 원문 URL은 정확한 학교 페이지로 연결하되, 학칙·졸업요건의 **원문 링크까지 금지**합니다. 학교 공식 문의처 경로는 별도로 제공합니다.
- **실제 코드와 출시:** `js/academic/`의 RulePack·FAQ·예측 모듈과 구형 REST `payload`의 존재는 기술 자산의 잔존이지 허용된 운영 기능의 증거가 아닙니다. `READY`는 기술적 유효 상태이지 학교 승인·학사 판단을 뜻하지 않습니다.

### 3.2 UI 동결과 서면 회신의 우선순위

과거 UI 기준선 [`ui-freeze.json`](../scripts/baselines/ui-freeze.json)은 사용자 승인 없는 임의 변경을 막기 위한 계약입니다. **정보처의 로고/엠블럼·공식 오인 금지 및 기능 금지는 우선하며, 해당 UI 보호 해시는 수정 작업에서 반드시 갱신**해야 합니다. 원본 기능 보호를 이유로 금지 상징물이나 졸업요건 탭을 계속 공개할 수 없습니다.

- **현재 상태:** 졸업 준비/FAQ 페이지·메뉴·학교 로고 파일을 제거했고 주요 화면에 비공식 문구를 표시했습니다. 사이트의 공식 수강신청 화면 유사성, 남아 있는 설명용 이미지·색채·이름은 추가 디자인/접근성 감사 대상입니다.
- **남은 목표:** 자체 한모 시각 정체성, 모든 주요 화면 비공식 문구의 가시성/콘텐츠 대비 검증, 원본 모의신청과 구별되는 디자인, 사이트맵·직접 URL·배포본에서 금지 자산 부재 재검증.
- **변경 승인:** 실제 HTML/CSS/이미지·파비콘은 승인 범위의 구현·디자인 검증과 baseline 갱신, 원본 모드/기본 OFF/대기/Enter·키보드·결과 회귀 후 공개합니다. 이번 사용자 승인과 제외 범위는 §3.3을 따르며, 실자료 연결·운영 배포 승인을 뜻하지 않습니다.
- **검증:** `npm run check`, `npm run test:e2e`, Windows Chrome/Edge 1280×720/1920×1080·200%·NVDA·브랜드 오인/비공식 고지 검사를 별개로 확인합니다.

### 3.3 이번 사용자 승인: 최소 디자인 개선

**2026-11-23 사용자 결정, 구현·CI 검증 완료, PR #128·#129 병합 확인.** [슬롭/의도된 디자인 200개 판단 기준](ai-slop-vs-intentional-design-200-signals.md)을 참고하되 기존 미니멀리즘과 **남색·금색**을 유지합니다. 장식이나 설명을 늘리지 않고 정렬·여백·글자 위계·키보드 접근·상태별 동작을 개선합니다. 페이지별 결정과 검증 근거는 [미니멀 UI 검토](minimal-ui-review.md)에 기록합니다.

- **보호 범위:** `practice`·`selectZone` 페이지 및 두 페이지가 사용하는 **공통 의존성 전체를 변경하지 않습니다**. 해당 HTML만 그대로 둔 채 공통 CSS/JS를 바꾸는 방식도 제외합니다. 다른 페이지의 수정은 분리된 파일·스타일 범위에서 진행합니다.
- **구조·폭:** 홈 링크를 실제 링크로 사용하고 키보드 포커스·진입을 제공합니다. 학업 화면의 대표 제목은 `h1`, 본문은 **최대 1184px의 중앙 정렬**을 기준으로 합니다. 필터·안내·상태·동작의 왼쪽 시작선을 맞춥니다. 기존 ‘최대 폭 없이 넓은 본문’ 결정은 이 승인된 기준으로 갱신합니다.
- **상태·문구:** `NOT_CONNECTED`에는 재시도 버튼을 숨기고, `OFFLINE`·`INVALID`에서만 수동 재시도를 제공합니다. 자료 없는 달력에는 **‘학교 일정 연결 전’**을 표시합니다. 문의처의 **‘검색 링크 만들기’ 버튼과 학교 홈페이지 링크**는 제거했습니다. 입력·예시 선택 시 외부 검색 링크를 준비하며 사용자가 직접 Google 링크를 클릭해야 이동합니다. 실제 빈도 자료는 미연결이므로 ‘예시 검색어’로 표시합니다.
- **구현·인수 구분:** 오픈소스의 기존 기능과 작은 모듈을 우선 활용하고 버전·라이선스를 관리합니다. 변경된 화면의 브라우저/CI 검증과 Windows Chrome/Edge·NVDA·200% 실기기 인수는 구분합니다. 데이터 수집·공개·Supabase는 계속 OFF입니다.

## 4. 1차 — 공개 공지 정밀 검색과 선택적 일정 탐색

**기존 ‘입학부터 졸업까지 자동 판정’ 목표는 종료합니다.** 현재 HTML·JS 코어가 남더라도 §0의 금지 기능을 사용자에게 공개하지 않습니다. 개발 작업은 합성 테스트, 허용된 정보 링크, 비식별 집계·예측의 재현성, 학교 공식 문의처 안내에 집중합니다.

### 4.2 공지 메타 정밀검색 — 1순위 기능 계획

**학생 기능 우선순위:** 허용된 공지의 제목·분야·게시일을 **빠르고 정확하게 검색해 원문으로 이동**하게 하는 #53·#40을 우선합니다. ‘변경 있음’ 전용 필터·정정 전후 비교표는 **요구사항에서 제외**합니다. 내부 중복/정정/철회 정보는 잘못된 검색 결과·구판 재노출을 막기 위한 무결성 검사에만 사용합니다. 기존 상세 매일 재조회·과거 백필·누락분 후속 큐는 하지 않습니다.

- 로그인 없이 공개된 공지의 **제목·게시일·출처·카테고리 등 메타데이터/원문 링크를 활용한 고급 검색·정규화·랭킹·내부 중복/정정 안전 처리와 비복제 구조화 가공**을 목표로 합니다. 이는 운영자가 전한 대면 가공 설명의 적용 대상입니다. 공지 **본문·첨부파일 그대로 복제/재게시 금지**, 교수명·수강 관련 정보 제외, 개인별 학적/졸업요건 판정 금지. 실제 색인은 서면 수집 제약을 넘는 범위까지 포괄한다고 광고하지 않습니다.
- 공지 적용 대상·학생 신청자격·학생 마감·정정/취소는 별도 증거 없이는 확정·추천·D-day로 표현하지 않습니다. 출처 최신성·일치성·링크 오류·철회 시 결과 표시를 보류하고 학교 원문 확인을 안내합니다.
- 기존 `notice-extract.js`·정규화/랭킹/주제 분류 코어는 **검수된 허용 공개 메타데이터의 검색과 내부 중복·정정·철회 안전 처리에 맞게 재설계**합니다. 공지 원문 전체를 보존·복제해 전문 검색/원문 재게시하는 방식 및 학교 제도/자격 판정은 제외합니다.
- 학생이 입력한 전공·입학년도는 공식 공지 대상 조건의 확인값이 아닙니다. 자동 공지 마감 알림 및 학생별 중요공지 확정은 별도 사용 범위가 확인되기 전 보류합니다.

### 4.3 강의 개설 집계·비공식 전망

- 허용된 공개 강의시간표 접근/주기는 §0.1에 한정됩니다. 과거 학기 목록·공식 API는 **제공되지 않으며**, 누락된 학기는 미개설로 해석하지 않습니다.
- 대면 안내에 따라 **공개 개설 이력의 과목명·학수번호·학기·캠퍼스별 개설 관측, 비식별 집계, 출처 범위·관측 건수·결측·확인일**의 가공/분석을 기능 범위로 설계하고 필드별 검수합니다. **교수명·서면의 '수강 관련 정보'는 제외**하며 개별 분반·정원·신청 상태 등 해당 표현에 저촉될 수 있는 항목은 이용 가능으로 단정하지 않고 검수 전 노출을 보류합니다. 누락 관측을 미개설로 추론하지 않습니다.
- 전망은 **한모 자체 산출물**, 학교가 제공·검증한 정보가 아닙니다. `k/n`은 관측 빈도로만 표시하고 정식 확률·개설 확정·시간표·수강 가능성을 보장하지 않습니다. 자료가 불충분하면 추정하지 않습니다.
- 기존 `html/catalog.html`, `html/forecast.html`, `js/academic/` 예측 코어의 **과거 개설 추세·학기별 이력 검색·비공식 전망**은 공지 검색과 독립된 검수·확장 후보입니다. 새 공개 메타데이터 DTO·금지 필드 분리·출처/결측·철회 및 자동 수집 제한이 통과하기 전 실제 데이터를 연결하지 않습니다. 교수명, 금지 수강 정보, 학생 신청 자격 판단·실제 대체과목 추천은 제외합니다.

- 요청 권한·소스 페이지·수집 가능 날짜·허용 필드를 확인할 수 없으면 **수집/저장/노출하지 않습니다**. 기존 `NOT_CONNECTED/EMPTY/OFFLINE/INVALID/READY` 런타임 오류 구분은 유지합니다.

## 5. 2차 — 기존 모의수강신청 실전 시나리오

**학교 서면 회신 우선:** 이 절의 기능은 오직 자체 합성 연습입니다. 학교 수강신청 시스템과 혼동될 수 있는 화면·마크·명칭은 수정해야 하며, 기존 외형을 보존한다는 이유로 공식 오인 금지를 무시하지 않습니다. 학교 로그인·실제 신청·실제 정원 조회는 연결하지 않습니다.

BASIC 오른쪽 아래 **돌발상황**은 `RECONNECT`(1회 가상 404)와 `CAPACITY`(BASIC에서 무작위로 한 과목의 정원 마감) 두 예/아니오를 각각 기본 OFF로 제공합니다. CAPACITY가 ON이면 마감된 강좌 신청 버튼이 사라지고, Search를 누르기 전 라디오만으로 관심강좌·전공·교양·기초의 조회 조건을 바꿀 수 있습니다. Search를 누르면 전공·교양·기초는 합성 대체과목만 보여줍니다. 실제 강의 정원·신청 서버·실학사 자료와 연결하지 않으며, RECONNECT/접속 대기/원본 신청 버튼의 기본 동작을 보호합니다. [#116](https://github.com/ot4562-glitch/Hanmo_develop/issues/116)

**접속 대기 시간 세부 설정 (사용자 결정, PR #109):** 필수 SETTING의 기존 단일 접속 대기 예/아니오를 **'강의 신청에 적용할까요?' (예/아니오, 기본 예)**와 **'수강신청 페이지 접속 시에 적용할까요?' (예/아니오, 기본 아니오)**로 분리합니다. 설정 UI에는 구현 파일 이름·괄호를 노출하지 않습니다. 두 값은 독립적으로 저장·복원합니다. 기존 브라우저 저장 키 `waitingValue`는 강의 신청/기존 검색 대기 설정용으로 그대로 유지하여 이전 사용자 선택을 마이그레이션 없이 읽고, 신규 `waitingEntryValue`는 페이지 접속 대기 설정이며 이전 설정값이 없으면 아니오로 취급합니다. 페이지 접속 대기는 신청 페이지에 들어가는 BASIC·SELECT에서만 기존 합성 대기창 `waitingFunc()`를 재사용합니다. 대기 중 왼쪽 메뉴·검색·신청을 비활성화하고, 대기 취소 시 연습 화면으로 돌아가며 완료 후 정상적으로 사용할 수 있습니다. 시간 측정에서 두 대기 유형에 걸린 합성 대기 초를 제외합니다.

### 5.2 전환 시점의 가상 404·실제 브라우저 복구 (RECONNECT)

- **발생 시점:** BASIC 모드에서 옵션 ON → 원본 `practice.html` 실행 → 기존 시작 대기/원본 `selectZone.html` 진입 → 새 정적 `incident-404.html`로 **1회 이동**. 선택만으로 즉시 404를 띄우거나 0~6초 타이머로 중간에 보여주지 않습니다. 실제 HTTP 응답은 정적 페이지 **200**이며, 학교 시스템·실제 네트워크 오류가 아닌 UI 모의 훈련입니다.
- **화면:** 수강신청 좌측 바는 원본과 유사한 시각 상태로만 보여 주고, `inert`/모든 버튼 disabled/키보드 포커스 제외로 클릭·Enter·Tab 활성화를 차단합니다. 오른쪽 정상 신청표·탐색·신청/삭제 버튼·기존 타이머는 모두 **숨긴 새로운 페이지**로, 가상 404 메시지와 브라우저 복구 안내만 남깁니다.
- **복구:** 페이지 내 버튼 없음. **지원하는 복구 안내는 Chrome 실제 새로고침(F5/브라우저 UI)뿐**이며, 감지 시 토큰을 소비하고 정상 `selectZone.html`로 `location.replace`합니다. 오류 화면에는 **'브라우저의 새로고침을 사용하세요.'**라고만 표시합니다. 브라우저 뒤로가기는 기록·캐시 상태에 따라 동작이 달라 **지원하거나 복구 방법으로 안내하지 않습니다**. 기존 뒤로/앞으로 캐시 상태 소비는 무한 오류 재진입 방어로만 유지합니다. `practice` 진입은 기존 `location.replace` 계약을 유지합니다.
- **신뢰 경계:** `sessionStorage`의 일회성 BASIC 토큰(선택·원본 practice 진입·전환 확인)은 다른 모드·직접 URL·만료/변조 상태에서 거부합니다. 초기 전환 30분, 오류 화면 새로고침 복구 유효성 5분을 상한으로 하되, 유효하지 않은 직접 오류 화면 접속은 정상 `selectZone`으로 복구합니다. 새 브라우저 탭의 최초 진입은 기본 OFF이나, 같은 탭에서 **확인**을 눌러 선택한 예/아니오는 독립된 `hanmo.synthetic404.selection.v1` 세션 키로 유지합니다. 메뉴로 돌아오거나 다시 로드해도 이전 선택을 표시하며, 취소로는 변경되지 않습니다. 선택 저장 키와 전환 토큰을 구분해 404는 새 BASIC 시작 시에만 다시 1회 발생하고, TIME/SELECT 실행이나 오류 복구가 선택 자체를 삭제하지 않습니다. 브라우저 세션이 끝나면 초기 OFF로 복귀하며 저장소가 차단되면 기본 OFF로 시작하고 장애 주입을 포기해 원본 연습으로 안전하게 진행합니다.
- **진입 버튼 버그:** `index.html`의 연습 버튼은 시간 제한 안내 중에도 표시·모드 선택 화면까지 이동할 수 있습니다. 기존 모의신청 실제 연습의 09:58~10:10 제한은 그대로이며, 이를 404 또는 메뉴 선택 기능으로 우회하지 않습니다.

(C) 학교 공식 API/과거 자료 일괄 제공은 **학교가 명시적으로 불가**라고 했으므로 대안에서 제외. 학교 서버 자동 수집은 A/B와 무관하게 §0.1을 통과해야 하며, 저장소를 쓴다고 수집권이 확장되지 않습니다.

### 7.1 최소 데이터 계약 (목표, 미구현)

**최초 검색 기능의 반입 범위는 허용 공지 제목·게시일·분야·출처·검수 메타로 제한**합니다. 일정 필드는 후순위 선택 확장, 관계·변경 필드는 잘못된 링크/철회 판본을 차단하기 위한 내부 감사 후보로 구별합니다. 아래의 개설 관측/집계 후보는 후속 검수 영역이며 이 기능에 함께 반입하지 않습니다. 신규 DTO v2·최대 행 수·보존 기간은 [최소 데이터 계획](focused-public-data-plan.md)을 따릅니다.

### 7.2 수집·검수·공개 흐름

```text
매 실행 전 운영자/학교 정책 확인
  → 허용 공개 URL·금지일·일별/학기별 예산·전역 락 검사
  → 단일 요청·간격 10초 이상·50건/실행 이내
  → 오류/차단이면 당일 즉시 중단 (재시도 없음)
  → 금지 필드·원문·첨부·학칙 제외
  → 최소 메타데이터/비식별 집계 산출
  → 출처·제외 범위·정정·권리/철회 독립 검수
  → 불변 정적 스냅샷 또는 제한된 공개 읽기 API
  → 비공식 표시·공식 원문 링크·확인 시각
```

- 위 흐름의 §0.1 수치는 전체 운영의 외곽 제한입니다. **공지 검색의 보수적 내부 예산은 게시판 1개부터 시작, 검수 후 최대 2개, 신규 상세 하루 최대 10개, 전체 HTTP 11~12건 이하, 15초 간격, 필요한 날 1회 이하**라는 더 작은 내부 예산을 적용합니다. 첫 목록을 초기 기준선으로 기록하며 과거 상세를 채우지 않습니다. 시간표 ≤2회/학기라는 외곽 한도는 시간표 크롤러 추가를 뜻하지 않습니다. 신청/정정 전후 각 1일까지 휴지하며 여러 인스턴스의 잠금·영속 카운터·KST·실행 로그로 우회를 차단합니다.
- User-Agent는 서비스명과 운영자 연락처를 포함하고 대상 웹사이트 상태를 존중합니다. 4xx/5xx 등 오류 응답/접속 제한이 발생하면 당시 배치 종료·그날 재시도 차단. 수집 거부와 학교 이용 조건 변경은 **즉시 OFF**로 처리.
- 초기 수집 범위는 **발행 가능한 메타데이터만**으로 줄입니다. 원문 전체를 복사하여 보관한 뒤 공개 직전에 필드만 지우는 방식은 채택하지 않습니다.
- 과거 관측 결측을 `NOT_OFFERED`로 추정하지 않습니다. 허용 집계라도 학교 확정 정보·시간표·수강 가능성으로 표현하지 않고, 학생에게 비공식 예상·자료 부족을 분리해 표시합니다.
- 권리 철회 시 **활성 스냅샷·CDN 캐시·색인·구판 롤백 경로**까지 제거/보류합니다. 복구가 권리 재사용을 뜻하지 않습니다. 검수·스냅샷 해시·공개/철회 기록은 운영자가 관리합니다.

### 7.3 공개 어댑터·보안·자료 책임

- 브라우저는 유효한 **비공식 최소 스냅샷/집계**만 읽습니다. 구형 학생용 `faq`·`instructor`·규정 데이터는 공개하지 않습니다. `NOT_CONNECTED/EMPTY/OFFLINE/INVALID/READY`는 기술적 연결 상태로만 해석합니다.
- 공개 DB/Data API에는 **RLS + 명시적 최소 GRANT + 허용 행만 SELECT**를 적용합니다. 공개 뷰의 RLS 우회, 관리자 `SECURITY DEFINER` 함수 호출 권한, 브라우저 secret/service_role 키 노출과 익명 쓰기를 금지합니다.
- 사용자 내정보·학점 입력은 브라우저 로컬에만 보관합니다. 공개 로그/분석/DB·학교 서버에 전달하지 않습니다.
- 운영 권한이 없는 임의 수집기·테스트 러너가 학교 서버에 접속하지 못하도록 기본 차단합니다. 스키마·RLS·네트워크·일정 경계 테스트는 **합성 요청/로컬 DB**로 먼저 수행합니다.
- 실제 공개 API 실연동은 권리·최소 필드·검수·운영자 인수와 별도 브라우저 QA가 끝난 뒤에만 결정합니다. SQL CI·정적 페이지 통과만으로 활성화하지 않습니다.

### 7.4 김채윤 담당·직접 실습 및 Free($0)

- **Supabase 관리 A/R:** 김채윤(`qamarrchae`; 2차 #71 완료 후 별도 Free 프로젝트 직접 생성·권한/비밀키·사용량·수동 백업/복원·RLS 실습). 실습 전에는 연결 OFF이며 합성 데이터만 사용합니다. **개발팀 R:** 축소 스키마/어댑터·수집 예산 테스트·RLS/장애 진단·복구 공동 대응. **자료 담당/독립 검수 R:** 허용 필드 확인, 정정·철회·집계 방법, 공표 오인 방지.
- 프로젝트 운영은 **Free만, 월 비용 $0**을 유지하며 유료 플랜/애드온 자동 전환을 하지 않습니다. 용량·egress 부족 시 범위 축소/정적 스냅샷·일시 중단이 우선입니다. 요금·한도는 운영 시 공식 가격표를 재확인합니다.
- **공지 검색·선택적 일정 데이터의 보수적 내부 예산:** DB 전체 **200MB 상한**, **160MB에서 점검**, Storage 128MB·전송 512MB/월 목표를 적용합니다. [산정표와 보존 계획](focused-public-data-plan.md)은 **추정이며 실제 DB 인수 결과가 아닙니다**. 테이블·인덱스·전체 DB·공개판·덤프를 실측하고 초과 예상 시 반입을 멈춥니다. 검수 장부 상한에 닿아도 승인·철회 근거를 임의 삭제하지 않습니다.
- 인계는 **마이그레이션, 최소 합성 데이터, 금지 필드 테스트, 요청 예산·전역 잠금/차단 기록, RLS 익명/관리자 권한, 철회·캐시/롤백, 백업·복구·긴급 OFF, 운영자 실제 재구축**으로 검증합니다. 정적/로컬 테스트와 실운영 인수는 구분합니다.
- 신규 스키마는 기존 #93 Draft의 허용되지 않은 구조를 그대로 이동시키지 않고, 필요 최소 객체로 별도 변경합니다. 작성자별 [PR 리뷰 규칙](../agent.md)은 그대로 적용합니다.
