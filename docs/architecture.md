## 0. 2026-11-23 서면의 명시적 금지·수집 조건 및 대면 가공 설명의 운영 해석

**근거:** [2026-11-23 정보처 서면 회신 원문(수정 없는 전문)](sources/2026-11-23-hufs-information-office-reply.txt) 및 [운영자 대면 설명·가공 방침과 긴급 철회 기록](public-data-operating-decision.md). 운영자는 **정보처 직원 두 명에게서 공개자료의 활용·가공이 가능하고 학교 서버에 부담을 주지 않으며 비공식임을 표시하라는 설명**을 대면으로 들었다고 전했습니다. 학교는 별도 과거 학기 파일·목록·API를 제공하지 않으며 서비스를 승인·인증·제휴하지 않았습니다. 운영 방침은 **서면에 명시된 금지사항은 금지, 자동 수집은 서면 수치/기간 그대로, 그 밖의 로그인 없는 공개자료 검색·가공·비복제 분석은 대면 설명을 참고해 운영자 책임으로 진행**하는 것입니다. 다만 서면 말미의 '**위에 적지 않은 이용은 허용하지 않습니다**' 조항과 이 해석은 충돌할 수 있습니다. 이는 학교의 공식적인 포괄 허가 확인이 아니며 철회·중단 요구에 즉시 대응합니다. 추가 문의는 당분간 하지 않습니다.

| 구분 | 현재 적용할 경계 |
|---|---|
| **서비스 표시·디자인** | 모든 주요 화면에 “본 서비스는 한국외국어대학교의 공식 서비스가 아니며, 정확한 정보는 학교 원문을 확인하시기 바랍니다” 수준의 **눈에 띄는 비공식 고지**. 학교 로고·엠블럼 및 공식처럼 오인되는 이름·디자인 금지. “학교 승인”, “학교와 협의”, 공식 인정·보증 표현 금지. 모의신청 화면도 실제 수강신청 시스템과 구별 |
| **공개 학사공지** | 로그인 없는 공개 페이지의 **제목·게시 메타/원문 링크를 고급 검색·정규화·랭킹하고, 내부 중복·정정 안전 처리**. 공지 본문·첨부 그대로 재게시하지 않고 교수명·수강 관련 정보·개별 적용 판정 제외 |
| **강의 개설 이력·전망** | 대면 공개정보 가공 설명을 기준으로 공개 개설 이력·과목 메타데이터의 검색/추세를 개발·필드별 검수 대상으로 포함. **교수명·'수강 관련 정보'는 서면 금지대로 제외**. 금지 표현과 충돌할 소지가 있는 개별 분반·정원·수강 항목은 위험 기록/검수 전 공개 보류. 학교 공식 개설/수강 판정으로 오인 금지 |
| **절대 제한** | 학교 자료를 이용한 학칙·졸업요건의 링크·인용·요약·표·자동 확인, 규정 기반 졸업학점 계산·졸업 가능 판정 **금지**. 학교를 대신한 학사 제도/절차 FAQ 답변 **금지**. 학교 계정 수집·대리 로그인·개인 성적자료 취급 **금지** |
| **책임·변경** | 자체 가공 정보는 학사 판단의 근거가 아님. 실제 수강신청·졸업·마감은 학교 공식 공지·시스템 기준. 정확성·결과 책임은 서비스 운영자에게 있으며 학교는 이용 범위를 변경·철회하고 접속을 차단할 수 있음 |

**두 안내의 권한·유효성:** 운영자 추가 설명에 따르면 이메일과 대면 안내 **모두 정보처 직원 차원의 응답이며, 학교 기관의 확정된 공식 이용 정책이 아닙니다.** 학교 도메인 이메일이 있다고 학교 차원의 영구 허가·기관 승인으로 해석하지 않습니다. **자료 항목과 수집 가능 범위는 향후 확대될 수도 축소될 수도** 있습니다. 그러나 확인된 새 기준이 나오기 전까지 한모는 현행 서면의 구체 금지/수집 제한을 자체 기본 운영 경계로 지킵니다. 변경 근거·필드별 재심사·긴급 중단/재개를 [잠정 정책 ADR `1.1](public-data-operating-decision.md)에 기록합니다. 2026-11-23 정책은 고정 불변인 학교 공식 규칙이 아닙니다.

### 0.1 자동 수집 계약 · 위반 시 실패 폐쇄

- 대상은 **로그인 없이 공개된 화면에 노출된 주소**만. 학사시스템 내부 주소·화면에 나타나지 않는 엔드포인트·보호 페이지/우회 경로 호출 금지.
- **학사공지:** 1일 1회 이하. **첫 목록 페이지만** 조회하고, **새로 올라온 공지의 상세 페이지만** 확인.
- **강의시간표:** 학기당 2회 이하. 이 한도는 별도 파일/API 제공 허락이나 상세 수강 정보 재배포 허락이 아님.
- 모든 요청 **간격 최소 10초**, **동시 접속 1개**, **1회 실행당 최대 50건**. 여러 작업자·러너가 있어도 전역 실행 잠금/횟수 장부로 합산 강제하고, 수동 실행이나 배포 재시작으로 초기화·우회하지 않음.
- **수강신청·수강정정 기간 및 각 기간의 시작 전 1일·종료 후 1일 전면 수집 금지**. 학사일정의 정확한 금지 구간을 확인하지 못하면 실행하지 않음. 특히 수강신청 기간에는 절대 자동 수집하지 않음.

**2026 동계 계절학기 신청 차단 일정(운영자 제공, 2026-11-23):** 날짜·시간은 `Asia/Seoul` 기준입니다.

| 사용자 전달 신청기간 | 신청 접수 시간 | 정보처 서면에 따라 자동 확장한 **전일 수집 금지** |
|---|---|---|
| **2026-11-25 ~ 2026-11-27** | 매일 **10:00~16:00** | **2026-11-24 00:00 ~ 2026-11-29 00:00 미만** (11/24~11/28 날짜 전체) |
| **2026-12-01 ~ 2026-12-03** | 매일 **10:00~16:00** | **2026-11-30 00:00 ~ 2026-12-05 00:00 미만** (11/30~12/04 날짜 전체) |

단지 10:00~16:00만 막지 않습니다. 해당 신청일 전체와 시작 전·종료 후 각 하루도 수집 금지입니다. 11/29처럼 위 구간 외의 날도 **다른 수강신청·정정 일정 전체가 공식 확인되지 않았으므로 자동 수집 가능일로 간주하지 않습니다.** 이 일정은 사용자가 전달한 2026년 정보로, **학교의 모든 신청/정정 일정이 검증됐다는 증거가 아닙니다.**

- [`data/collection-blackouts.json`](../data/collection-blackouts.json): 날짜·매일 10~16시·KST·전후 1일과 `partial` 검증 상태를 보관하는 단일 정의.
- [`scripts/collection-window.mjs`](../scripts/collection-window.mjs): KST 달력 날짜를 기준으로 앞뒤 1일을 자동 확장하고, 신청일·여유일의 00~24시 내내 차단. 다른 일정 미검증·연결 OFF·수집기 예산 미구현은 **실행 불허**로 처리.
- `npm run collection:status -- --at 2026-11-25T11:00:00+09:00`은 외부 요청 없이 조회만 함. `npm run collection:gate`는 **실제 시스템 시각으로 판정**해 차단이면 비정상 종료하며 테스트용 임의 시각 인자를 허용하지 않음.
- 지금은 실제 HTTP 크롤러/스케줄러가 **없고 `mode: disabled`**입니다. 학교 자료를 가져오는 동작은 추가하지 않으며, 향후 수집기 진입/개별 요청 전 이 게이트 및 #66의 전역 요청 예산·오류 차단을 연결하고 **전체 일정의 공식 검증·독립 운영 인수 전에는 활성화하지 않습니다.**

- **오류 응답이나 접속 제한이 한 번이라도 발생하면 즉시 중단하고 그날 재시도 금지**. 지수 백오프·자동 복구 재시도·우회 IP·대체 크롤러 등으로 계속 요청하지 않음.
- User-Agent에는 **한모 서비스명과 운영자 연락처**를 기재. 사용자별 요청·배치와 무관하게 서버 부하가 예상되면 즉시 중단. 차단은 사전 통보 없이 가능.
- 수집 기능은 **초기 OFF**, 네트워크 접근 전 허용 출처 목록·전역 속도 제한·요청 예산·실행/학기 카운터·금지 날짜·오류 차단·긴급 정지 스위치를 테스트하며, 학교가 조건을 변경·철회하면 즉시 수집/공개를 중단함. 실제 크롤러는 아직 승인된 구현이나 실행 상태가 아님.

### 0.2 금지 기능·기존 구현·배포 차단

**웹 1차 정리 반영:** 졸업 준비 `html/academic-progress.html`과 학사 FAQ `html/academic-faq.html`, 전용 CSS·FAQ JS, 학교 로고 `img/hufs_logo.png`는 [웹 정리 커밋](https://github.com/ot4562-glitch/Hanmo_develop/commit/2712bd939502a31755fd21026ac96fe81650c552)에서 삭제했습니다. 메뉴·사이트맵·빌드·테스트도 수정했습니다. **학교 학칙/졸업요건·FAQ 계산 및 근거형 답변의 순수 코어와 옛 데이터 소스 계약은 코드에 남을 수 있지만 운영 기능은 아닙니다.** 학교 자료 연결 `mode: disabled`를 유지하고 웹 디자인·접근성/실기기 검수는 별도 완료 게이트입니다.

학교 문양을 사용하던 기존 홈·상단바·이미지·파비콘·SVG·메타정보와 실제 수강신청을 연상시키는 화면은 **별도 수정 및 브라우저 QA 대상**입니다. 기존 UI 동결 정책은 새 서면 금지사항을 보존할 근거가 아니므로 관련 변경을 우선하되, 원본 동작·실기기 회귀·디자인 구별을 확인합니다. **2026-11-23 웹 1차 정리로 금지된 페이지·학교 로고 파일 제거와 비공식 고지를 반영했습니다. 그러나 디자인 전수/Windows 실기기 QA, 원본 운영 도메인 공개·학교의 서비스 인정은 완료되지 않았습니다.** `data/academic-source-config.json`의 `mode: disabled`를 유지하고, 금지된 필드가 포함된 기존 Supabase Draft #93·공개 payload는 수정·재설계 전 활성화하지 않습니다.

### 0.3 운영자 최종 해석(2026-11-23) · 공개자료 가공 이용과 즉시 철회

**데이터 항목에 관한 대면 안내 재확인:** 운영자가 전한 정보처 직원 두 명의 설명은 공개자료의 단순 열람뿐 아니라 **검색·분류·집계·분석·가공도 가능한 취지**였습니다. 운영자는 **서면에서 구체적으로 금지된 항목을 제외한 공개자료 활용은 대면 안내로 판단**, 자동 수집 조건은 **서면에 적힌 제한을 전부 그대로 준수**하기로 했습니다. 이전의 '합성 데이터 기능 개발만 허용하고 모든 추가 공개정보 이용은 서면 재확인 전 보류'라는 지나치게 좁은 운영 결정을 이 기준으로 수정합니다. 추가 학교 문의는 당분간 진행하지 않습니다.

학생 기능은 공지 메타데이터 정밀검색·필터·오타 교정·공식 원문 이동을 우선합니다. 과거 공개 개설 관측의 추세와 학기별 비교는 필드 검수 후 검토합니다. 달력은 월간 보기와 공식 일정 링크를 유지하며, 검수된 날짜 표시는 [#127](https://github.com/ot4562-glitch/Hanmo_develop/issues/127)에서 후순위로 다룹니다. 독립 문의처 화면, 변경 공지 전용 필터, 정정 전후 비교는 범위에서 제외합니다. 수집·검수·비용 상한과 필드별 판단 기준은 [최소 데이터 운영 계획](focused-public-data-plan.md)과 [공개자료 운영 방침](public-data-operating-decision.md)을 따릅니다.

**주의:** 서면의 '위에 적지 않은 이용은 허용하지 않습니다'라는 포괄 문구가 여전히 존재하므로 대면 설명에 근거한 추가 가공 범위는 **운영자의 해석·위험 수용이지 학교의 공식 확대 허가로 확인된 것이 아닙니다**. 학교 요청/정책 변경·오류 시 수집과 데이터 노출을 즉시 중단하고 정적 번들/DB/캐시/이전 배포본까지 철회합니다. 구체적인 근거·필드별 판단표·절차는 [공개자료 운영 결정](public-data-operating-decision.md), 구현/검증 과제는 [#41](https://github.com/ot4562-glitch/Hanmo_develop/issues/41)·[#66](https://github.com/ot4562-glitch/Hanmo_develop/issues/66)·[#126](https://github.com/ot4562-glitch/Hanmo_develop/issues/126)을 참조합니다. **현재는 데이터 연동 `mode: disabled`, 크롤러/통합 킬 스위치 미구현**입니다.

## 3. PC 진단 상세

사용자가 직접 진단 시작을 눌렀을 때만 측정합니다. 브라우저에서는 `requestAnimationFrame` 예열 0.5초+실측 약 3초, 프레임 간격 중앙값/P95, `max(50ms, 중앙값×3)` 이상 끊김, 가능할 때 `PerformanceObserver` 긴 작업(50ms+), 타이머 지연 P95를 관측합니다. `hardwareConcurrency`·`deviceMemory`·`NetworkInformation`은 브라우저 지원 시 추정치만 표시합니다.

한모 동출처에서만 HEAD 5회와 `data/network-probe.txt`의 GET 2회를 실행합니다. 요청마다 캐시 우회와 5초 타임아웃을 적용하고 리디렉션을 거부합니다. Resource Timing의 요청 전체 시간으로 HTTP 응답 중앙값을 구하고, 연속한 유효 요청 차이의 중앙값을 지터로 보고합니다. 다운로드는 약 262KB 시험 파일의 완전한 수신을 확인한 뒤 전송 인코딩이 반영된 본문 크기를 요청 전체 시간으로 나눕니다. 브라우저 캐시, 서비스 워커 개입, 전송을 확인할 수 없는 표본은 실패와 구분해 집계합니다. 사용자가 취소하거나 탭이 숨겨지면 결과를 확정하지 않습니다. CDN 관측은 회선의 공인 Mbps나 학교 수강신청 성능을 나타내지 않습니다.

진단 결과 아래에는 실제로 관측된 이상에 해당하는 권장 조치만 표시합니다. 화면 끊김·갱신 지연은 화면 설정, 긴 작업·타이머 지연은 브라우저 부하, 반복 요청 실패는 한모 연결 확인과 재검사를 안내합니다. 중복 조치는 묶고 단발 실패·표본 제외는 측정 제한으로 구분합니다. 미지원·미실시 지표 및 CPU·메모리·네트워크 유형의 추정치만으로 새 이상 판정을 하지 않습니다. 정상 결과에는 불필요한 조치 목록을 표시하지 않으며, 재검사 시 이전 안내를 교체합니다.

## 4. 반응속도 테스트 상세

사용자가 시작하면 0.9~2.3초의 무작위 준비 시간 뒤 프레임 콜백에서 초록 신호를 표시합니다. 신호를 설정한 시각과 마우스 버튼을 누르거나 Space를 누른 입력 이벤트의 시각 차이를 8회 수집합니다. 이 값은 브라우저에서 추정한 반응시간이며 실제 패널의 표시 시각을 측정하지 않습니다. 신호 전 입력, 80ms 미만 또는 3000ms 초과 반응, 탭 숨김은 이번 측정을 폐기합니다. **결과 문구는 “사용자님의 반응속도는 중앙값 Nms 입니다.” 한 줄**이며 P90과 변동폭은 전략 실험에만 사용합니다.

`hanmo.reaction.profile.v1`을 `localStorage`에 보관합니다. 저장에 실패하면 중앙값과 저장 실패 안내를 표시합니다. 전략 실험은 저장소에 접근할 수 없거나 프로필 형식이 잘못됐거나 측정 후 30일이 넘으면 프로필을 적용하지 않습니다. 다른 탭의 프로필 변경은 전략 실험 화면에 반영합니다.

## 5. 전략 실험: 가상 정원 1~300

사용자 입력은 **가상 과목명, 중요 순위(1이 제일 높음), 가상 정원 1~300명, 경쟁자 수 0~200명**만. 가상 과목은 2~8개, 중요 순위 1~N을 중복 없이 설정합니다. **50명 이하 제한은 오류였으며 2026-11-23 수정 완료([d7d87f7](https://github.com/ot4562-glitch/Hanmo_develop/commit/d7d87f7eaa1056ecb59d8cfb91927255d3a78792)).** 300 허용/301 거부 테스트를 유지합니다.

- **자동 입력.** `Asia/Seoul` 시각으로 시드를 생성해 결과에 표시합니다. 사용자 반응 프로필의 중앙값과 P90으로 기준 행동시간 및 변동을 설정합니다. 380ms는 Fitts 조작시간의 기준점(거리 240px, 폭 60px)이며 신청별 가상 조작시간은 달라집니다. 같은 입력·프로필·시드로 같은 결과를 얻습니다.
- **경쟁자가 여러 과목을 신청하는 정도.** 최대 수요 D_max=max(D_i)와 후보군 내 최대 수요 과목 신청 비율 ρ로 후보군 G=ceil(D_max/ρ)를 결정합니다(경쟁자 없음은 G=0). 낮음·기본·높음 ρ=0.25·0.5·0.75입니다. 과목마다 정확히 D_i명을 독립적으로 중복 없이 균등 추출합니다. 두 과목의 예상 교집합은 D_iD_j/G, 다른 과목에 이미 속한 경쟁자가 과목 i에도 속할 조건부 확률은 D_i/G입니다. 사용자 입력 과목 수만 늘어날 때 최대 수요가 같다면 후보군은 일정합니다. 미배정 후보는 서버 모형에서 제외합니다. 이는 독립 배정과 합성 중복도이며 실제 전공별 수강 집단은 미확보입니다. 경쟁자별 전체 신청량 K_v=max(m_v,X_v), X_v~DiscreteUniform{5,6,7,8}, m_v는 배정된 입력 과목 수입니다. 나머지를 입력 목록 밖 과목으로 채웁니다.
- **오픈 직후 선착순·개인별 선택 모형.** 경쟁자는 목록을 중복 없이 신청합니다. 입력 과목 가중치는 u_i=sqrt(1+D_i/C_i)입니다. 기타 과목의 경쟁 가중치는 입력 과목의 u_i에서 균등 복원추출해 입력 여부로 인한 구조적 우선순위 편향을 줄입니다. 경쟁자별 로그 선호 η_bvi~N(0,0.7²), q_bvi=u_i exp(η_bvi)를 사용해 Plackett–Luce 순열을 지수 경주 방식으로 추출합니다. 기타 과목도 서로 다른 선호를 가집니다. 반응시간은 계층적 사전 예측 모형입니다. 회차별 μ_b=270+Uniform(−30,30)ms이며 모든 비교 조건에 공유됩니다. 개인별 U_bv~LogNormal(−0.35²/2,0.35²) 및 R_bv=80+(μ_b−115)U_bv를 한 번 생성해 모든 신청에 유지합니다. 신청마다 독립 ε_bvs~N(0,25²)ms와 Y_bvs~Exp(rate=1/35)ms를 더해 max(80,R_bv+ε_bvs+Y_bvs)를 계산합니다. 이는 이동 로그정규 개인 위치를 가진 계층적 Ex-Gaussian 반응의 하한 처리입니다. 하한 처리 전 평균은 μ_b이며 하한 처리 이후에는 다소 달라집니다. 데이터에 적합시킨 사후분포가 아닙니다.
- **비동시 진입.** 기준 즉시 시작 비율 α=0.75로 0ms, 나머지 0.25로 Uniform(0,30000)ms 시작 지연을 생성합니다. 지연은 최초 요청에만 영향을 미치며 기존 반응·Fitts·1~3초 기본 응답과 분리합니다. 후보군과 난수는 동일한 전원 동시 시작(α=1) 민감도도 별도 평가합니다. 75%, 30초 및 5~8과목은 실측 보정값이 아니라 명시적인 합성 시나리오입니다. 실제 연구의 시간 규모나 모집단은 한국외대에 그대로 전이하지 않습니다.
- **Fitts 조작시간.** 본인과 경쟁자 각각 신청 순번별 거리 d~Uniform(80,480)px, 유효 폭 w=60px를 별도 난수 계열에서 생성하고 J(d,w)=380+110 log₂((1+d/w)/5)ms를 적용합니다. 본인의 행동시간은 J+max(80,a−380+σZ), 경쟁자는 J+max(80,R+ε+Y)입니다. 기준 a·σ는 기존 반응 프로필의 중앙값·P90으로 계산합니다. 실제 목표 거리나 개인별 Fitts 계수 측정은 하지 않으며 키보드와 마우스의 조작 차이를 따로 적합하지 않습니다. 과목 순열과 무관한 순번별 조작시간을 유지하여 DP의 전제를 보존합니다.
- **공통 비정상 FCFS 서버 대기열.** 유한 모집단의 첫 요청과 이후 응답 의존 요청에서 도착률이 내생적으로 달라집니다. 가상 서버의 처리율은 시작 후 0~2초 50건/초, 2~5초 80건/초, 이후 100건/초입니다. 시간 단위 ms에서 처리율 c(t)는 0.05, 0.08, 0.1건/ms이며 시작 B=max(T, 이전 처리 종료), 종료 E는 B부터 E까지 c(t)의 적분이 1이 되는 시각입니다. 경계에서 남은 작업량에 새 처리율을 적용합니다. 기본 응답시간 L은 1,000~3,000ms(양 끝 포함) 균등 정수 난수이며 응답 완료 F=max(E,B+L)입니다. 본인과 입력 과목에 배정된 경쟁자의 모든 요청(목록 밖·실패 포함)을 동일한 최소 힙 기반 대기열에서 도착순으로 처리합니다. 동시 도착은 고정 참가자 ID 순서(본인 마지막)입니다. 혼잡 대기는 B−T, 전체 응답 대기는 F−T이며 참가자는 응답 후 다음 행동을 시작합니다. 응답의 남은 시간은 서버를 점유하지 않습니다. 시간 의존 처리율은 과목 종류 및 성공 여부에 독립이므로 기존 순열 DP를 유지합니다. 기준 조건의 별도 평가에서 평균 누적 대기·혼잡 대기·마지막 응답까지 소요시간을 표시합니다. 실제 서버 처리율·학교 전체 접속자·학년별 우선권·페이지 진입/검색 대기를 추정하지 않으며 기존 BASIC/TIME/SELECT 모의신청 대기창은 변경하지 않습니다.
- **추천 순서와 결과.** 본인의 서버 처리 완료 시각이 정원 번째 경쟁자 처리 완료 시각보다 빠르면 성공입니다. 기준 조건의 1,000회로 과목별·순서별 성공 빈도를 계산하고, 비트마스크 DP로 중요 순위 가중치 `w=N−rank+1`에 따른 기대점수가 가장 높은 순서를 고릅니다. 순서 선택에 쓰지 않은 1,000회씩으로 같은 순서의 전체 성공률을 ρ=0.25·0.5·0.75 및 전원 동시 시작(ρ=0.5, α=1) 조건에서 집계합니다. 기준 조건의 평가 표본으로 과목별 성공률과 기대 성공 과목 수도 계산하여 전 과목 성공 미관측에서도 부분 성과를 나타냅니다. 마지막 본인 요청 처리 후에는 성공 여부를 바꿀 수 없는 이후 요청을 생략합니다. 경쟁이 있는 상태에서 성공이나 실패가 한 번도 나오지 않으면 미관측과 관측 횟수를 표시합니다. 복수 과목 신청 정도·우선순위·신청별 대기시간은 합성 가정이며 실제 학교 서버의 대기시간이나 우선권을 추정한 것이 아닙니다.
- **수식 보기.** 결과에서 기본 접힘인 `details#strategy-formulas`를 열면 실제 적용된 N·M·행동시간·변동폭·시드, 행동·대기시간 함수, 경쟁자 후보군과 선택확률, 요청·마감시각, 가중 기대점수 최대화 목적함수와 독립 평가 표본의 전체 성공률·시간 추정식을 볼 수 있습니다. 상세 설명과 수식은 현행 `strategy-engine.mjs` 및 `reaction-profile.mjs`를 기준으로 유지합니다. 네이티브 MathML로 분수·근호·합·곱·아래첨자를 렌더링하고 외부 수식 라이브러리나 CDN을 사용하지 않습니다. 회차별 집단 평균·이동 로그정규 개인 위치·신청별 Ex-Gaussian 변동, Fitts 법칙, 개인별 Plackett–Luce 선택 및 시간 의존 공통 대기열을 명시합니다. 각 MathML 수식의 가로 스크롤을 제거하고 긴 조건식은 여러 행으로 표현합니다. 결과 영역의 세로 스크롤은 유지합니다. 추천 순서의 성공률 뒤 `(기본 가정)` 문구는 삭제하되 ρ=0.5, α=0.75 기준 및 전원 동시 시작 조건은 수식 영역에 명시합니다.
- 메인 스레드가 아니라 Web Worker에서 수행하며 취소 시 Worker 종료. 모의신청 BASIC의 CAPACITY 옵션(한 과목 가상 마감)과 이 전략 모델의 `capacity` 입력은 **서로 다른 독립 기능**입니다.

### 5.1 현행 모델 유지·검증 우선 (2026-11-25)

전략 실험은 합성 몬테카를로 기반 개인 신청 전략 도구로 현재 기능 구성을 유지하고 안정화·재현성·설명 가능성·민감도 검증을 우선합니다. 실제 학생 선호·진입·경쟁 중복·신청량·서버 처리율은 미보정입니다. 성공률을 높이기 위한 임의 모수 조정이나 추가 분포·제도 비교·실학교 예측을 당장 개발하지 않습니다.

- **입력 및 계산 계약:** 이름·중요 순위·가상 정원·경쟁자 네 필드만 유지. 반응 프로필의 8회 측정 중앙값/P90/변동폭, 30일 유효기간과 시간 기반 시드 자동 적용. 추천 순서 선택 표본 M=1000과 조건별 별도 평가 표본 M=1000은 분리합니다. 공통 난수와 후보군의 재현성, 확률 범위, DP의 기대 가중점수 최대화, 각 과목 성공률·기대 성공 과목 수와 전체 성공 사건의 일관성을 검증합니다. 평균 가중 기대점수는 순서 선택 표본의 값이며, 실증 예측 정확도 또는 전체 동시 성공률 최대화가 아닙니다.
- **민감도/불확실성:** ρ∈{0.25,0.5,0.75}, α∈{0.75,1}, 경쟁자 전체 신청량·목록 밖 경쟁률·서버 처리율·행동시간은 명시적 합성 가정. 0/1000 성공은 실제 확률 0이라는 뜻이 아니며, 1000/1000도 구조적 보장(모든 정원 > 경쟁자) 외에는 확정 100%가 아닙니다. 실제 확률의 신뢰구간으로 해석하지 않습니다. 동시 성공에 대한 예측 신뢰도는 관측 자료 없이는 주장할 수 없습니다.

### 5.2 적용한 모형의 연구 근거 및 검증 한계

- 신진이·이상원(2016), 「시뮬레이션을 통한 선착순 수강신청 시스템 개선」, 한국정보과학회 한국컴퓨터종합학술대회 논문집, 1736–1738쪽: 제공된 3쪽 원문을 검토했습니다. C++ 시뮬레이션으로 선착순·마일리지·추첨·타임티켓을 비교하고 5개 전공과 교양, 전공별 과목 인기, 학생 인터넷 속도 X~N(3,1), 우선순위 큐, 트래픽 오류/지연 없음, 과목 종류·선호에 따른 만족도를 가정합니다. 마일리지의 만족도 향상은 10%p 이하로 보고했으며 나머지 세 방식의 만족도 차이는 크지 않았습니다. 소스코드와 재현에 충분한 상세 알고리즘·실험 규모/모수는 제시되지 않습니다. 한모는 개인 전략 목적이며 Fitts/계층적 반응/공통 대기열을 별도로 구현합니다. 전공별 선호 구조는 연구 후보로만 남기며 논문 수치를 보정값으로 전용하지 않습니다. 원문 PDF는 재배포하지 않습니다.
- [Multi-Unit Assignment Problem: FCFS Course Allocation System Data Analysis (2017)](https://www.journals.vu.lt/statisticsjournal/en/article/view/13869): 실제 수강신청과 합성 선호 생성의 비교. 한모는 관측치가 없어 선호를 가정으로 생성합니다.
- [임성민·김진흠 (2013), 사회 네크워크 분석으로 본 수강신청 행태](https://www.kci.go.kr/kciportal/ci/sereArticleSearch/ciSereArtiView.kci?sereArticleSearchBean.artiId=ART001800039): 과목 공동 수강 네트워크. 현재 중복 확률을 분리하되 실제 커뮤니티는 추정하지 않습니다.
- [Siefken (2017), Registration Delay and Student Performance](https://doi.org/10.14434/josotl.v17i2.20754): 신청 시작 지연의 이질성. 해당 모집단과 시간 척도는 한모와 달라 75%·30초의 근거로 해석하지 않습니다.
- [Bichler·Merting (2021), Randomized Scheduling Mechanisms](https://doi.org/10.1111/poms.13449): 복수 과목 묶음에 대한 선호와 FCFS 배정. 한모는 배정 제도 자체가 아니라 개인 전략을 실험하므로 기존 FCFS와 순서 최적화를 유지합니다.

- [Rouder 외 (2005), 계층적 반응시간 분포 모형](https://pubmed.ncbi.nlm.nih.gov/16082801/) 및 [2008 계층적 ex-Gaussian 추정 비교](https://pmc.ncbi.nlm.nih.gov/articles/PMC2601029/): 개인 간·개인 내 변동의 동시 추정과 정보 공유. [2023 계층적 로그정규 모형 튜토리얼](https://doi.org/10.1111/bmsp.12302): 혼합모형 등 확장. 이동 로그정규 개인 위치와 Ex-Gaussian 신청 변동을 결합했습니다. 충분한 동의 기반 연습 데이터로 후보 분포의 표본 외 성능을 비교할 수 있지만 현재는 사전 예측만 수행합니다.
- [MacKenzie (1992), Fitts 법칙](https://www.yorku.ca/mack/hci1992.html): 반응시간과 별개인 마우스 이동·목표 선택 시간. 합성 목표 거리/폭의 Fitts 함수를 적용했습니다. 사용자별 실제 선택·확인 시간과 키보드 조작 계수는 아직 미측정입니다.
- [Turner 외 (2020), Plackett–Luce 순위 모형](https://doi.org/10.1007/s00180-020-00959-3): 개인별 선호 가중치를 가진 합성 Plackett–Luce 규칙을 적용했습니다. 실제 동의받은 선호 순위/선택 목록이 있다면 선호·경쟁률·시간 충돌·공통 수강 집단을 반영한 혼합 선택 모형을 비교할 수 있습니다.
- [Honnappa 외, On Transitory Queueing](https://arxiv.org/abs/1412.2321): 시작 직후 요청 집중처럼 유한 모집단·유한 시간·비정상 도착의 대기열을 다루는 틀. 실제 학교 전체 도착/응답/처리율 자료는 확보되지 않았으므로 시간에 따라 달라지는 처리율을 가상 시나리오로 적용했습니다. 별도 배경 요청은 실제 근거가 없어 추가하지 않았습니다.
- **합성 회귀 비교(2026-11-25).** 고정 시드 123456789, 사용자 중앙값 250ms, 기준 행동 630ms, 변동 40ms, 기존 기본 3과목 및 정원 15명·경쟁자 30명 추가 과목, 학습 200회·독립 평가 200회에서 기존/수정 전체 성공 횟수는 3과목 55/198, 5과목 0/120, 8과목 0/0이었습니다. 수정 조건의 기대 성공 과목 수는 2.99, 4.515, 4.50개이며 전원 동시 시작의 전체 성공 횟수는 190, 35, 0회였습니다. 이는 모형 민감도 비교이지 예측 정확도 검증이 아닙니다. 결과를 강제로 높이는 보정은 하지 않습니다. 전체 신청량·입력 밖 과목 가중치·후보군 중복도·진입 분포에 대한 별도 실측이 필요합니다.
- 근사 베이지안 계산(ABC)은 이번 구현 범위에서 제외합니다.
- [Stable reliability diagrams (2021)](https://pmc.ncbi.nlm.nih.gov/articles/PMC7923594/): 독립 관측 성공 여부를 확보하면 Brier 점수와 신뢰도 곡선으로 보정과 표본 외 성능을 검증합니다. 독립 반복에 따른 몬테카를로 오차와 구조적 모형 불확실성을 구분합니다. 현재는 실제 성공률의 추정 정확도나 교내 자료 접근을 주장하지 않습니다.
