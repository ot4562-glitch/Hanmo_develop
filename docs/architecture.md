# Hanmo Develop — 아키텍처

> 현재 유효한 제품 및 기술 설계입니다. 실제로 구현된 기능과 앞으로 구현할 목표를 구별합니다.  
> **이 문서는 변경 이력이나 회의록이 아닙니다.** 설계가 바뀌면 이전 안을 남기지 않고 현재 안으로 수정합니다.

## 1. 프로젝트 목표

한모를 **수강신청할 때만 방문하는 모의연습 사이트**에서 **입학 후 수강계획부터 졸업까지 지속적으로 이용하는 비공식 학업 플랫폼**으로 확장합니다.

- **포함:** 학기별 강의·분반·담당교수, 시간표·대체과목, 학점·재수강·이수요건, 주전공·이중전공·부전공, 수강신청·전공신청·학사공지·학사일정, 졸업시험·논문·인증·졸업사정, 학적·학점교류, 학칙 개정 영향, 강의 개설·학사행사 전망, 근거형 학사 FAQ, 학업 상담 경로, 교환학생·국제학생 학업 준비.
- **제외:** 고용·취업·진로·채용·직무 멘토·NCS, 실제 학교 수강신청 자동화, 학교 계정 인증 대행, 공식 졸업사정의 대체.
- **일관성:** 기존 BASIC / TIME / SELECT 모의신청의 화면·조작 충실도를 지킵니다. 학생에게는 **현재 부족한 것, 근거, 다음에 할 일, 불확실성**을 함께 제시하며, 학사 판단은 검증된 규정과 적용 대상이 확인되는 범위에서만 안내합니다. 계산 가능·소스 이식·화면 작동·공식 검증·출시 적합은 별도 상태입니다.

## 2. 개발 단계 및 책임 범위

| 단계 | 우리 팀의 완료 목표 | 기존 한모 코드 | 외부 DB |
|---|---|---|---|
| **1차 — 학업 플랫폼** | 독립 추가 페이지·계산 엔진·입력/저장·테스트 완성 | **수정 금지** | 없이 작동 |
| **2차 — 실전 모의신청** | 기존 연습화면에서 선택형 실패·대체검색·재접속 시나리오 완성 | **원개발자 협의 및 승인 후** 변경 | 없이 작동 |
| **3차 — 데이터 연동** | Supabase DB·수집·검증·갱신·보안·배포 설계 **및 인계 완료** | 별도 협의 | **우리 팀은 개설·운영하지 않음** |

우리 팀은 **1·2차의 실제 구현과 검증**에 집중합니다. **3차의 Supabase 프로젝트 개설·소유·운영 및 실제 서비스 연동은 임창용 님과 협의**하고, 우리 팀은 바로 실행에 옮길 수 있을 정도의 설계와 인수 기준만 전달합니다. 2차의 기존 페이지 변경 및 최종 병합·배포에도 원개발자 승인이 필요합니다.

**현재 작업 원칙은 설계 정제 및 선별 병합 준비입니다.** 이미 이식한 코드 전체를 자동 승인하지 않고 학업 기능별 채택·제외·수정 조건을 먼저 정합니다. 아키텍처 개정은 기능 구현·PR 병합·운영 배포 승인이 아닙니다.

## 3. 시스템 구성

```text
[1·2차: GitHub Pages + 브라우저, 별도 서버/DB 불필요]
기존 한모 BASIC / TIME / SELECT ──(원개발자 승인 시에만 2차 확장)
  └─ 합성 모의신청 상태 (실제 취득학점·학교 신청 상태와 절대 분리)

/degree-rescue/ 독립 학업 플랫폼
  ├─ 학생 조건·로컬 이수 원장·수강계획·체크리스트
  ├─ 학칙 RulePack → 학점/졸업 감사 → 변경 영향·What-if
  ├─ 강의/교수 표시 검색 → 시간표/대체과목 → 개설 전망
  ├─ 부족 요건·관심 강좌 → 공지/신청/제출/달력 → 공식 원문
  ├─ 학사행사 예상 구간, 근거형 학사 FAQ, 교환·국제 학업 준비
  └─ HTML/CSS + 브라우저 TypeScript 순수 계산 코어
                  ↑
        데이터 검증/판본/신뢰 경계
                  ↑
  검수된 정적 자료(릴리스 포함) / 미검수 사용자 JSON·CSV(로컬만)

[3차: 설계·인계만 / 현재 미구축]
허가된 한국외대 공개 자료 → 변경 감지 → 독립 검수·승인
  → Supabase 구조화 데이터·판본/권리/감사 이력
  → 읽기 전용 API/스냅샷 어댑터 → 동일한 학업 계산 코어
```

### 3.1 실행 경계

- **정적 우선:** React 의존 화면은 정적 HTML과 DOM 이벤트로 재구성하고, TypeScript 계산 로직은 파일·로컬 저장소·추후 API와 분리합니다. 1·2차는 인터넷이나 인증 서비스가 없어도 사용자가 제공한 자료와 번들 예제로 작동해야 합니다.
- **단일 진실의 출처:** 공식 확인을 주장하는 자료는 운영 검수된 릴리스 자산과 그 판본·해시에서만 채택합니다. 형식 검증에 통과한 사용자 파일은 비공식 자료입니다. 학교 자료를 자동 갱신하지 못하는 경우 마지막 검수시각을 표시합니다.
- **학생 정보:** 학번 대신 입학년도·캠퍼스·전공·적용 교육과정 등 필요한 조건만 입력합니다. 개별 성적/이수/학적 파일은 사용자가 로컬에서 불러와 관리하며 원격 전송·공개 Git 기록·서버 기본 동기화가 없습니다. 브라우저 데이터 삭제·내보내기·공유 PC 주의를 제공합니다.
- **재사용 자산:** `degree-rescue/src/`에는 선택된 브라우저 실행 코어와 테스트만 둡니다. `legacy-academic/`의 React·Fastify·PostgreSQL·공용 비학업 타입은 참조용이며 **번들/정적 공개 파일에 포함하지 않습니다**. 235개 보존 소스 전체는 병합 대상이 아닌 선택·권리 검토 후보입니다.
- **원본 보호:** 1차 동안 한모 루트 `index.html`, `html/`, `js/`, `css/`, `img/`, `CNAME` 수정 0건. 루트 원본 한모의 커스텀 도메인을 미병합 학업 기능의 미리보기로 사용하지 않습니다.

### 3.2 제품 기능 상태의 별도 판정

| 상태 | 정의 | 완료 판단에 대한 제약 |
|---|---|---|
| 설계 채택 | 사용자 흐름·계약·검수 게이트가 정의됨 | 코드·화면 존재를 의미하지 않음 |
| 순수 코어 이식 | 브라우저에서 호출 가능한 검증/계산 함수와 테스트 확보 | 사용자 입력 UI·공식 자료 확보를 의미하지 않음 |
| 참조 코드 보존 | React/API/옛 소스를 직접 빌드 없이 조회할 수 있음 | 실행 기능이나 허용된 재배포를 의미하지 않음 |
| UI 시제품 | 정적 화면에서 로컬/합성 데이터로 동작 | 실학생의 공식 학업 판정을 의미하지 않음 |
| 서비스 준비 | 출처·판본·권리·접근성·브라우저 QA 및 운영 책임 통과 | 별도의 병합·배포 승인 필요 |

**단일 학생 경험:** 첫 화면은 JSON 원문 대신 캠퍼스·학번 연도·전공·목표 학기와 입력 자료를 확인받고, 학생의 '부족 요건 → 계획 변경 → 근거 공지 → 행동/마감'으로 이어집니다. 고급 JSON 입력/검사 화면은 내부 진단 도구로 남길 수 있으나 이를 서비스 완료로 계산하지 않습니다.

## 4. 1차 — 입학 후부터 졸업까지의 학생용 학업 플랫폼

추가 화면은 `degree-rescue/` 독립 주소에만 구축합니다. 코어는 공식 규정·출처가 검증되지 않으면 사용자 입력에 대한 **조건부 결과/확인 필요**만 반환하며, 학교의 신청·성적·졸업 확정 기능을 대행하지 않습니다. 아래 항목은 **채택한 목표 기능과 계산 계약**이고, 실제 학생 화면/정본 데이터 구축 여부는 별도로 검증합니다.

### 4.1 학생 프로필·이수 원장·졸업 계산

- **적용 조건:** 서울/글로벌 캠퍼스, 입학년도, 입학전형·교육과정 버전, 주전공·이중전공/부전공·전공심화 선택, 학적/등록학기, 목표 졸업학기를 명시합니다. 필수 축이 없거나 전공 변경 이력이 불명확하면 정확한 RulePack을 임의 선택하지 않습니다.
- **학점 상태 분리:** `EARNED`(취득 완료), `IN_PROGRESS`(수강 중), `PLANNED`(계획), `PENDING`(인정 미확정), 공식 제외/재수강 무효화를 분리합니다. `1 credit unit = 0.5학점`의 정수 단위를 사용하고 과목 동일성·중복·재수강 승인·취득 학기 종료 시점을 검증합니다. 수강 중/계획 학점을 이미 취득한 학점으로 합산하지 않습니다.
- **요건 범위:** 총학점, 교양필수/영역, 전공필수·선택, 필수·동일/대체 교과목, 선택묶음, 영역 분포, 학점교류·교환·편입 인정, 재수강/학점포기, 등록학기, 평점 요건의 확인 가능성, 졸업시험/FLEX·논문·언어 인증·서류·졸업사정의 비학점 조건을 각기 분리합니다.
- **결과 계약:** 요건별 `SATISFIED / UNSATISFIED / NEEDS_REVIEW / NOT_CHECKED / NOT_APPLICABLE`과 근거 조항·계산 판본·남은 학점 또는 확인할 사유를 제공합니다. 전체 요약 `READY`는 **검증한 입력에 대한 계산 상태**이지 '졸업 승인'이 아닙니다. 출처가 모자라면 `INSUFFICIENT_DATA`, 규칙·이수 여부가 충돌하면 `NEEDS_REVIEW`로 보류합니다.
- **전공 변경 What-if:** 주전공 변경, 이중전공 신청/변경/포기, 부전공 전환, 전공심화 경로에 따른 전후 부족 요건과 수강 계획을 비교합니다. 변경은 가정일 뿐 실제 전공 배정, 지원 자격, 합격이나 학칙 적용 변경을 단정하지 않습니다.
- **장기 경로:** 남은 요건, 학기별 최대학점, 과목 선후수, 같은 학기 실제 개설 가능성, 대체 과목과 학적 변경을 고려해 2~4학기 계획 A/B/C와 졸업 지연 위험을 비교합니다. **현재 한 학기 제약 검사 코어와 구별되는 신규 최적화 기능**이며 공식 강의·교과과정 정본 없이는 조건부 시나리오로만 표시합니다.

### 4.2 학칙 원문 승인·판본 관리·학생별 개정 영향

- **RulePack 키:** 캠퍼스·학번 범위·주/이중/부전공·입학전형·교육과정/트랙·적용 시작/종료·규정 버전. 같은 조건에서 승인된 규정이 둘 이상 충돌하거나 예외의 적용 범위가 확정되지 않으면 자동 선택을 중단합니다.
- **원문 재현성:** 학칙 조항·단서·예외·각주를 빠짐없이 독립 목록으로 만들고 `sourceSpanRef`, 원문 URL·해시, 조항 ↔ `requirementId` 양방향 연결과 숫자 일치 여부를 확인합니다. 원문 목록 자체를 후보 RulePack과 동일한 도구가 생성했다면 독립 검수가 아닙니다.
- **승인 게이트:** 검수자와 승인자를 서로 다른 역할로 두고 적용 시점·공개 시점·검토 시각·원문 판본·범위·개정 승계 관계를 확인합니다. `APPROVED` 문자열이나 사람 이름을 사용자 JSON에 넣었다고 실제 승인이 되지 않습니다. 문제가 있으면 기존 검증 판본을 유지하거나 '확인 필요'로 처리합니다.
- **개정 비교:** `rule-approval.ts` 및 `rule-diff.ts`의 개념을 채택합니다. 안정적인 `semanticKey`/요건 ID를 전제로 같은 학생 이수 원장을 개정 전·후 RulePack에 적용해 `ADDED / REMOVED / CHANGED / UNCHANGED`와 `GAINED / LOST / SAME / UNKNOWN`을 구분합니다.
- **변경 영향 화면:** 학생에게 '새 필수과목', '충족 → 미충족 가능', '면제/대체 인정 변경', '추가 확인/이수 필요', '적용 대상 아님/불명'을 근거 조항과 함께 설명합니다. 학사 적용일·학번 소급 규정은 임의 해석하지 않습니다. 과목의 영역 재분류가 바뀌었다면 새로운 분류 원장(`nextAttempts`)이 없는 경우 결과를 확정하지 않습니다.
- **판본 역행 방지:** 이전 규정의 충족 결과를 새로운 규정으로 그대로 복사하지 않습니다. 개정 체인 단절·중복/겹침·승인되지 않은 규정·규정 ID 변경을 발견하면 차이표를 보류하고 학생에게 확인할 원문을 제공합니다.

### 4.3 강의·교수 표시·시간표·계획 스냅샷

- **검색:** 학수번호·과목명·학기·캠퍼스·분반·학점·개설학과·요일/시간·강의실·담당교수 **표시명**. 과목 고유 식별자, 분반/개설 학기, 수업 담당 이력을 분리합니다. WIS 수동 저장 HTML/CSV의 형식·중복·학기·범위·출처를 검증합니다.
- **자료 사실성:** 로컬 WIS 저장본에 나오는 교수 이름은 해당 수업의 표시명이지 재직·인사·지도교수·연락처/강의평가 정본이 아닙니다. 사용자 제공 CSV는 형식 검사를 통과해도 `UNVERIFIED`입니다. 과목 코드에서 분반을 자동 분리하거나 제목만으로 동일 교과목이라고 추정하지 않습니다.
- **수강계획 검증:** 한 학기 학점 상한, 선수요건, 시간표 충돌, 인정 영역, 이미 들은 과목, 분반 개설 상태를 함께 검사합니다. 확인된 분반이 없으면 강의·시간을 가상 생성하지 않고 `확인 필요`로 남깁니다. 대체 과목은 공식 동등성·학칙 범위가 확인되어야 '인정 가능'이라고 표기합니다.
- **계산 스냅샷:** 학칙 `rulePackVersion`, 이수 원장 `ledgerVersion`/`transcriptVersion`, 강의·분반 `catalogVersion`, 사용자 계획 `planVersion`, 행사·공지 자료 `noticeSnapshotVersion`, `asOf`, 적용 조건 및 출처 목록을 결과마다 결합합니다. 판본·시간표·폐강·정정·규정 승인/철회 중 하나라도 바뀌면 이전 결과는 `STALE / 재계산 필요`가 되며 저장된 추천을 재사용하지 않습니다.
- **재현성:** 동일 스냅샷과 동일 입력은 동일 결과를 내야 합니다. 단순 파일명/문자열 버전이나 로컬 체크 상태는 공식 소스의 최신성/승인을 증명하지 않습니다. 버전 하나가 누락되면 그 자료를 참조한 결과만 안전하게 보류하고 잘못된 부분 갱신을 막습니다.

### 4.4 학사공지·신청기간·미충족 요건에서 행동까지

**학생 → 규정·이수 원장 → 미충족/확인 요건 → 필요한 과목·신청·제출 → 적용 공지·실제 마감 → 담당 부서/원문 확인**을 하나의 사용자 흐름으로 연결합니다.

| 영역 | 공지 및 행동 | 연결할 학생 조건 |
|---|---|---|
| 수강 | 사전신청, 본신청·정정·철회, 계절학기, 개설·폐강 | 부족 과목·분반·학점 상한·선수 요건 |
| 전공 | 주전공/세부전공, 이중전공 신청·변경·포기, 부전공·전공심화 | 학번·학적·전공 조합·지원 조건 |
| 졸업 | 졸업시험/FLEX, 논문, 외국어 인증, 사정·제출 서류·수료·학위 | 비학점/학점 요건·목표 졸업학기 |
| 성적·학적 | 성적 정정·재수강·학점포기·학점교류 인정, 휴·복학·등록 | 원장 인정 상태·학적·등록학기 |
| 국제·지원 | 교환학생 지원·학점 인정, 학사 FAQ, 교직/학업 상담 | 언어·이수학기·캠퍼스·관련 교육과정 |

- **공지 출처 계약:** 공지 ID/개정 ID, 게시/정정/취소 시각, 작성 부서, 원문 URL, 학생 적용 범위, 학생 접수 마감 `studentDeadline`, 행정 보고 마감 `adminDeadline`, 시험/행사일, 공지 유형·학기, 근거 요건 `requirementRefs`·과목 `courseRefs`를 구분합니다. 게시일은 접수 마감일이 아니고 행정 마감은 학생 D-day가 아닙니다. 모든 날짜는 `Asia/Seoul`로 표시·계산합니다.
- **학생 대상 판정:** 캠퍼스·학번·전공 역할·학적·졸업 목표·요건별 상태 중 필요한 값이 없으면 `UNKNOWN`; 명확히 불일치하면 `NO`; 충분히 확인되면 `YES`. 자기 입력 졸업 목표만으로 공식 졸업예정자 신분을 추정하지 않습니다.
- **요건 자동 연결:** `openRequirementIdsFromAudit`와 공지 `requirementRefs`를 연결하되 **동일한 검증 RulePack의 요건 ID**여야 합니다. 학생이 직접 적거나 정적 계산에서 도출한 '미충족 후보'는 공지를 찾아주는 힌트일 뿐 '공식 충족/비대상'을 판정하지 못합니다. 후보가 없다는 이유로 필수 공지나 검토 필요 공지를 숨기지 않습니다.
- **공지 정정/취소:** 동일 ID 판본 충돌·미래 게시·철회/취소·권리 회수·출처 불명은 격리하고 과거의 확인된 공지를 무조건 되살리지 않습니다. 동일 제목 여러 개를 하나의 확정 마감으로 합치지 않습니다.
- **중요도 모델:** 검수되고 적용 대상이 `YES`인 필수 공지 중 **학생 마감 7일 이내**를 최우선(`CRITICAL_DUE`), 그다음 학업 필수(`ACADEMIC_REQUIRED`), 학생 관심/직접 관련(`PERSONAL`), 일반(`GENERAL`)로 분류합니다. 미검수 후보는 검토 목록으로 분리하며 확인된 필수 공지로 격상하지 않습니다. 지난 마감은 '기한 경과·담당부서 확인'으로 표시하고 상단 고정 대상에서 제외합니다.
- **상단 고정/캘린더:** 검수된 미경과 필수 공지만 **최대 2건 상단 고정**합니다. 달력은 '개최일/시험일', '학생 신청 마감', '사용자 개인 목표'의 표식을 달리하고, 날짜 미확정·취소·대상 미확인 항목은 별도 확인 목록에 둡니다. 공식 확정 D-day와 미검수 사용자가 입력한 참고 날짜를 절대 동일하게 표현하지 않습니다.
- **개인 졸업 체크리스트:** 14개 항목의 자기 점검과 공식 규정 기반 충족 판정을 **별도 열/상태**로 표시합니다. 수동 `DONE`은 '본인이 확인함'에 불과하며 학교의 이수·인증 완료를 뜻하지 않습니다. 각 행의 미충족 요건·근거 공지·준비 행동·확인 부서로 탐색할 수 있도록 합니다.

### 4.5 강의 개설 전망 및 반복 학사행사 예상 구간

- **강의 개설:** 같은 시즌의 과거 개설·미개설을 관측값으로 사용하고 공식 확정 공지·개설 목록은 가장 높은 우선순위로 별도 표시합니다. 누락된 학기를 미개설로 채우지 않으며 관측 범위/완전성을 표기합니다. `k/n`을 곧바로 미래 확률 `k/n × 100%`로 표시하지 않습니다. 가정 변경·rolling-origin 백테스트를 통과하지 않은 확률 보정은 보류합니다.
- **반복 학사행사:** `campus-assist/activities.ts`가 제공하는 행사 계열(교내 학사 행사/전공 신청/졸업시험 등)의 과거 개최일을 연도별·공식 원문별로 묶습니다. 서로 다른 **최소 2개 연도**의 유효한 개최 근거가 있어야만 계절성 구간을 추정합니다. 현행 이식 코어는 개최일 분산 **45일 초과 시 보류**, 전후 **약 7일 여유**의 대략적 기간을 생성하는 휴리스틱입니다. 이는 학교의 공식 예정일/신청 시작·마감일이 아닙니다.
- **정정/취소 우선:** 해당 연도의 검증된 일정·취소·정정이 예측보다 우선합니다. 날짜 없는 취소가 어느 회차를 가리키는지 불명확하면 예측을 중단합니다. 출처 권리·검증일·대상 계열·과거 연도 간 충돌을 확인해야 하며, 자료가 불충분할 때 인위적인 D-day를 만들지 않습니다.
- **학생 표시:** `확정된 행사일`, `과거 이력 기반 예상 구간`, `근거 부족/취소 확인 필요`를 다른 시각/문구로 보여줍니다. 예상 구간에는 신청 버튼·확정 마감 알림을 연결하지 않고 공식 공지를 확인하도록 유도합니다.

### 4.6 근거 중심 학사 FAQ·교내 학사 상담 안내

- **검색:** 학교에서 재사용이 허용된 한국어 학사 FAQ·공지의 문단을 원문/개정 판본·권리 상태·검증 시점별로 관리하고, **BM25 문자 bigram** 기반 결정론적 검색을 제공합니다. 별도 서버 LLM 없이 근거 문단·원문 링크·관련 적용 조건을 표시합니다.
- **답변 검수:** `faq-guard.ts` 수준의 검사로 인용 문구의 원문 존재 여부, 숫자·금액·날짜의 근거, 원문의 **부정/예외/조건 표현 보존**, 미지원 주장, 링크·연락처의 불시 생성, 개별 학생의 합격/지원 자격 확정을 차단합니다. 불확실하면 정답 문장을 꾸미지 않고 근거 문단과 확인할 담당 부서를 나열합니다.
- **개정 및 철회:** 동일 문서의 최신 검증 판본을 사용하되 동일 판본 간 내용 충돌, 최신 판본 권리 철회/차단/만료, 출처 시각이 조회 시각보다 늦은 경우 문서를 제외합니다. 과거 정답을 조용히 되살리지 않습니다.
- **상담 연결:** 학생 질문 목적(학칙/이수/학적/국제교류 등)과 캠퍼스에 맞는 **공식 학사 담당 부서·공개 안내 페이지**를 최대한 관련성 있게 안내합니다. 외부 상담/예약 시스템을 연동하거나 예약 완료·교수 배정·학교 답변을 가장하지 않습니다. 진로·취업 상담과는 분리합니다.

### 4.7 교환학생·국제학생·학업 지원(선택 확장)

- **교환학생 준비:** 파견 유형·파트너 대학·신청 학기, 평점/이수학기/편입·휴학 여부, 언어 요건, 파견기관별 조건, 귀국 후 학점 인정 절차를 **공식 확인 체크리스트**로 구성합니다. 현행 `exchange-preparation.ts`는 `READY_FOR_OFFICIAL_REVIEW / NEEDS_EVIDENCE / HAS_BLOCKERS / STALE_POLICY` 등의 준비 상태를 표현할 수 있으나 학생의 실제 지원 자격·합격이나 신청 성공은 판정하지 않습니다.
- **조건 상태:** 학교 확인/본인 진술/자료 누락을 구분하고, 개정된 교환 정책·다른 학교/학기·판본과 맞지 않는 결과는 무효로 둡니다. 학교에서 검증하지 않은 평점·언어 성적을 '확정 충족'으로 표시하지 않습니다. 신청기간이 공식 자료에 없으면 마감 날짜를 만들어내지 않습니다.
- **국제학생 안내:** 입학/등록/휴복학/수강/졸업/증명 등 학업 절차별로 한국어·영어·중국어 자료를 지원하되 **사람이 검토한 번역본**이 원문 `revisionId`와 일치할 때만 표시합니다. 원문이 개정/권리 철회되거나 번역본 판본이 어긋나면 한국어 최신 검수본으로 안전하게 대체하거나 `확인 필요`로 보류합니다.
- **국제학생 체크 상태:** 사용자가 저장한 체크리스트는 해당 안내문 판본·선택 언어·번역 버전에 묶습니다. 원문/번역이 바뀌면 옛 체크를 현재 검증된 절차 완료로 이전하지 않습니다.
- **학업 지원:** 학습 프로그램·교직/공식 학사상담 정보는 **학업 목적에 직접 해당할 때만** 제한적으로 사용할 수 있습니다. 진로·경력·취업 멘토, 일반 기회 추천, 학생 프로파일링·모델 점수로 지원 가능성을 확정하는 기능은 제외합니다.

### 4.8 학생용 화면·로컬 데이터·완료 조건

- **화면 구조:** '내 학업 현황', '학칙 변경 영향', '강의/시간표', '이번 학기 해야 할 일·공지', '학사 달력', '근거 FAQ', '학업 준비 체크리스트'로 연결합니다. JSON 직접 편집은 선택적 고급/진단 경로로 분리합니다.
- **사용자 조작:** 로컬 자료 불러오기·미리보기·오류 확인·명시적 저장·백업·삭제, 목표 졸업학기/전공/수강계획 비교, 공지 원문 열기, 검증 시각/적용 대상 확인이 가능해야 합니다. 같은 탭 내 로컬 계산 결과 전달은 **최소 요건 ID와 판본/기준 시각**만 사용하고 원장 원본/성적을 다른 페이지에 광범위하게 전달하지 않습니다.
- **명확한 정보 계층:** `공식 원문 검수`, `출처 URL만 확인`, `사용자 입력`, `합성 예시`, `과거 기반 예상`, `자료 부족/규정 충돌`을 시각적·텍스트로 분리합니다. 화면의 신뢰 표시는 브라우저 파일이 스스로 설정한 상태값이 아니라 별도 승인된 자료와 일치해야 합니다.
- **접근성:** 키보드만으로 검색·필터·마감·달력·체크리스트를 조작할 수 있고, 화면낭독기 날짜/상태 안내와 모바일 폭에서 과도한 표 가로스크롤을 피합니다. 시간대·요일·D-day가 한국시간 기준인지 명확히 표기합니다.
- **출시 조건:** 합성 단위 테스트뿐 아니라 학교 정본 RulePack·공지/강의 표본의 수기 대조, 실제 브라우저 회귀, 권리·공식성 고지, 원본 한모 무변경이 필요합니다. 어떤 화면도 공식 수강신청·학칙 승인·학위 취득을 확정하지 않습니다.

## 5. 2차 — 기존 모의수강신청 실전 시나리오

**원개발자 승인 후 별도 PR로 개발합니다.** 기본 BASIC/TIME/SELECT는 그대로 유지하고 사용자가 원할 때만 돌발상황을 실행합니다. 독립 새 연습 페이지가 아니라 **기존 연습 페이지와 입력 흐름의 선택형 확장**이 목표입니다.

### 5.1 마지막 강좌 신청 실패 (LAST COURSE FAIL)

1. 목표 N개 과목과 예비 대체 강좌를 설정합니다. 연습 데이터는 합성 강좌가 기본입니다.
2. 재현 가능한 훈련에서는 처음 N−1개의 신청이 성공하고 마지막 목표 1개가 **가상 정원 마감** 등의 사유로 실패합니다.
3. 학생은 연습을 종료하지 않고 **직접 다른 과목을 검색·선택·모의신청**합니다.
4. 시간/학점/선수요건/이수영역/기신청 강좌와 충돌하면 무효입니다. **대안이 없는 상황을 정확히 확인하는 것**도 올바른 대응입니다.
5. 원래 목표 달성·대체 확보·미해결·잘못된 대체 선택으로 결과를 나눕니다.

### 5.2 튕김·재접속 (RECONNECT RECOVERY)

- 진입 직후, 일부 신청 후, 확인창 대기 등 설정한 시점에 **가상 세션 단절**을 만듭니다.
- 학생이 모의 재접속·대기열·진입을 수행하고 **성공 확인/결과 불명/미신청 과목**을 구분합니다.
- 결과 불명 신청은 성공으로 간주하거나 중복 신청하지 않습니다. 실제 학교 사이트에 접근·자동 로그인하거나 네트워크를 끊지 않습니다.
- 정원 마감·긴 대기열·충돌·취소 실수·복합 위기 등 난이도를 추가할 수 있습니다.

**평가:** 단순 클릭 속도보다 복구 성공, 유효한 대체과목, 실패 인지 및 대응 시간, 실수·중복 신청, 검증된 학업계획 영향이 우선입니다. 시나리오 ID/난수 시드를 고정해 반복 재현합니다.

**시뮬레이션과 실제 강의의 경계:** 가상 수강신청 과목 코드와 공식 과목/분반 ID 사이의 연결은 명시적인 변환 계약으로만 수행합니다. 연습의 성공·취소·대기열은 실제 수강 확정이나 학점 취득을 뜻하지 않으며 이수 원장에 반영하거나 학교 시스템으로 전송하지 않습니다.

## 6. 1·2차 자료·검증·배포 원칙

- **출처 검증:** 공식 URL, 확인일, 적용 대상·기간, 학칙 판본과 `SYNTHETIC`·`REFERENCE_ONLY`·`SOURCE_REVIEWED`·`NEEDS_REVIEW`를 구분합니다. URL·검토 날짜·`SOURCE_REVIEWED` 필드를 JSON 파일 안에 적는 것은 **자체 선언**이지 운영 검수의 증거가 아닙니다.
- **검수 권한 분리:** 사용자 업로드·로컬 계산·단순 정적 참고 목록은 미검수로 받아들입니다. 검수된 학생 마감이나 공지를 제공하려면 별도 운영자가 원문·판본·대상·정정 이력을 확인한 배포 자산이 필요합니다. 현재 일정 코어는 입력 JSON 필드와 별도로 **검수된 데이터 객체 참조**를 전달받아야 검수된 공지로 인정합니다. 업로드 제공자는 스스로 그 참조를 만들 수 없습니다. 3차는 검수자와 승인자 권한, 승인 기록·철회·원문 해시를 관리합니다.
- **결과 신뢰성:** 사용자 학점·학칙 JSON은 계산 가능해도 공식 졸업 판정의 증거가 아닙니다. 출처·규정·원장·강의/계획 판본이 일치해야 사용하고 변경되면 계산을 무효화하며, 불명확한 적용 대상과 누락은 `확인 필요`로 남깁니다.
- **접근 범위:** 학교의 공식 API 및 공개 자료 접근/재사용 권한을 확인하며, 보호된 로그인/SSO를 우회하지 않습니다. 학교 시스템 오류나 확정 결과를 재현한다고 과장하지 않습니다.
- **개인정보:** 학생 성적 원본·학교 계정·비밀키를 공개 GitHub에 넣거나 자동 전송하지 않습니다. 브라우저 자료의 삭제/백업을 제공하고 공유 PC 이용을 안내합니다.
- **테스트:** 학점·전공·학칙·이중전공·공지 범위/KST 기한·학기 개설·시간표 제약·가상 복구에 대한 회귀/속성 테스트, 정적 빌드·브라우저 사용성·접근성 확인.
- **원본 보호:** 1차에서 기존 한모 프로그램 파일의 변경은 **0건**. 2차는 원개발자 승인 후에도 기본 모드의 포커스·키보드·시간·결과가 바뀌지 않아야 합니다.
- **권리:** 원본 한모의 GPL-3.0, HUFS One AI 팀 기여 코드 공개 재배포 권리, 학사자료 수집·사용 권리를 실제 병합·배포 전 확인합니다.

## 7. 3차 — Supabase 설계 인계

**아래는 앞으로 넘길 목표 아키텍처입니다. 실제 Supabase 프로젝트·자동 수집·DB 연동은 아직 구축하지 않습니다.** 원문 PDF/HTML/첨부파일은 저장하지 않고 필요한 구조화 정보와 **원문 링크·변경 이력**만 관리합니다.

### 7.1 핵심 데이터 계약

| 논리 테이블 | 필요한 정보 |
|---|---|
| `courses` | 학수번호, 이름, 학점, 이수영역, 동일/대체과목 연결 |
| `course_offerings`, `sections` | 학기, 캠퍼스, 개설 상태, 분반, 담당, 요일/시간, 장소 |
| `faculty`, `teaching_assignments` | 공개 교수 표시명·소속, 학기별 강의 담당 이력 |
| `academic_notices`, `notice_revisions` | 원문 식별자·URL, 게시 부서/표시, 게시·수정시각, 핵심 추출 내용, 대상, 정정/취소 |
| `academic_events` | 시작·신청/제출마감·시험일, 캠퍼스·학번·전공 대상 |
| `graduation_rules`, `program_requirements` | 전공/입학년도별 이수학점·필수과목·논문·시험·언어 인증·규정 판본 |
| `data_sources`, `sync_runs` | 출처·확인일·변경 해시 및 수집 상태 |
| `source_reviews`, `review_approvals` | 검수·승인자 역할, 자료 판본·해시, 검수/승인/철회 시각과 감사 기록 |
| `data_snapshots` | 강의·학칙·공지 판본 묶음, 유효 기간, 무효화 상태 (학생 개인정보 제외) |
| `event_series`, `event_occurrences` | 반복 학사행사 계열, 확정 개최·변경/취소·예상 구간과 근거 분리 |

- 데이터는 과목과 학기별 개설·분반, 교수와 담당 이력을 분리해 중복을 줄입니다. 공지 원문을 매번 복제하지 않고 변경된 판본만 보존합니다.
- 무료 DB **500MB는 실사용량·인덱스·행 오버헤드 측정 전 용량 보장치가 아닙니다**. 필요한 저장량·성장률·상위 요금제 이관 방안을 인계 설계에서 명시합니다.
- 학생 개인 이수·성적/계획은 기본적으로 로컬에 보관하며, 다중 기기 동기화는 별도 개인정보·인증 검토 후 선택형으로 설계합니다.

### 7.2 데이터 갱신 아키텍처

```text
공식 공개 학사자료 또는 허가된 API
  → 정기 수집(GitHub Actions / 승인된 워커)
  → 원문 식별자·수정일·해시로 변경 감지
  → JSON/CSV 핵심 필드 정규화와 규정·일정 검증
  → 검수·승인 → 현재값 및 필요한 이력 DB 반영
  → 공개 읽기 전용 API → 학업 플랫폼
```

학교가 공식 API 또는 자동 수집 권한을 제공하지 않는 경우 **실시간 자동 갱신을 보장하지 않습니다**. 오류·누락·취소·정정에 대비해 확인 시각, 보류 표시, 재시도와 **정적 JSON 대체 경로**를 둡니다.

### 7.3 인계에 반드시 포함할 산출물

- DB 스키마/관계도, 예시 데이터, 키·인덱스·변경판/규정 기간, SQL 마이그레이션 설계, 용량·비용·백업/복구.
- 공개 읽기 권한과 수집/검수 쓰기 권한 분리, RLS·보안 정책, 비밀키의 클라이언트 노출 금지.
- 자료 출처별 접근/재사용 조건, 갱신 주기, 수집 실패·정정/취소 처리, 검수자와 운영 점검.
- GitHub Pages 데이터 어댑터 전환, API 장애 시 로컬 대체, 테스트·배포·롤백 및 운영자 인수 체크리스트.
- 임창용 님의 프로젝트 개설·소유·운영·비용 승인, 원개발자 코드 병합과 데이터 사용 권한을 명시한 전달 문서.

## 8. 완료 판단과 현재 상태

| 단계 | 통과 조건 |
|---|---|
| **1차** | DB 없이 추가 페이지가 실제 사용 가능하고 계산·로컬 데이터·브라우저 QA를 통과. 원본 프로그램 불변, 공식 자료 부족은 미확인 처리 |
| **2차** | 승인된 기존 화면 확장과 실패/재접속 회귀 테스트 통과. 시나리오 미선택 시 기존 모드 동작 불변 |
| **3차** | 실연동 없이도 소유자가 개설/구현을 판단할 수 있는 DB·수집·API·보안·운영·전환 설계가 준비됨 |

**현재:** 기존 한모는 운영 중이고 학업 추가 기능은 미병합 개발 PR에 있습니다. 학교 전체 강의/학칙 정본, 실제 Supabase 데이터베이스와 자동 갱신은 연결되지 않았습니다. 계획과 실서비스 구현 완료를 구분해야 합니다.
