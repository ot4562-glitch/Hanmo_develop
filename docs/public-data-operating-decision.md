# 공개 학사정보 가공·탐색 운영 방침 · 중단 및 철회 절차

> **잠정 운영 방침(2026-11-23, 운영자 후속 설명 반영).** GitHub 공개 저장소의 개발 기록입니다. **정보처 직원의 이메일 회신과 두 직원의 대면 안내는 모두 학교 기관의 확정된 공식 입장으로 확인되지 않았으며**, 서비스 승인·제휴나 영구적인 데이터 사용권을 뜻하지 않습니다. 대면 설명은 운영자가 전달한 내용으로 녹취/학교 공식 문서로 검증된 별도 허가가 아닙니다.

## 1. 두 정보처 직원의 설명과 운영자 해석

- **대면 안내(운영자 전달):** 정보처 직원 두 명으로부터 로그인 없이 공개된 학교 자료는 학교 서버에 부담을 주지 않는 범위에서 활용할 수 있고, **검색·분류·집계·분석 등 가공도 가능**하다는 취지로 설명을 들었습니다. 학교가 과거 학기 목록·파일·API를 별도로 제공하지 않으며, 한모가 독립된 비공식 서비스임을 알리라는 조건도 들었습니다.
- **정보처 2026-11-23 이메일(직원 안내):** [서면 원문](sources/2026-11-23-hufs-information-office-reply.txt)은 **명시적 금지 항목**, **자동 수집의 수치/기간 제한**, **비공식 표시와 공식 원문 안내**를 포함합니다. 마지막에는 '위에 적지 않은 이용은 허용하지 않습니다'라는 포괄 조항과 **범위 변경·철회 가능성**을 적었습니다. **이메일도 학교 전체의 확정적인 공식 입장으로 확인된 것은 아닙니다.**
- **운영자 결정:** **① 서면에서 명시적으로 금지한 이용은 금지, ② 자동 수집은 서면 조건을 모두 적용, ③ 서면에서 개별적으로 금지하지 않은 로그인 없는 공개자료의 사용·가공·검색·분석은 대면 설명에 따른 내부 운영 해석으로 진행**합니다. 추가 문의는 당분간 하지 않습니다. 독립적으로 구현한 알고리즘 및 합성 테스트에만 한정하는 이전 방침은 여기서 수정합니다.
- **충돌의 투명한 기록:** ③은 이메일의 '열거 외 이용 불허' 문구와 **해석 충돌** 가능성이 있습니다. 따라서 한모의 자체 위험 수용 판단일 뿐 **학교가 이를 공식적으로 승인했다거나 이메일의 포괄 조항이 무효라고 단정하지 않습니다.** 요청/정책 변경이 있으면 대상 자료의 이용을 즉시 중단합니다.

## 1.1 안내의 지위와 데이터 범위 변경(운영 ADR)

**상태: 잠정(PROVISIONAL) · 기준일: 2026-11-23 · 공식 정책 확정: 아니오.** 직원 발신 학교 이메일이라는 점은 서면 안내의 출처를 확인해 주지만 **학교 전체를 구속하는 최종 정책·서비스 공식 승인이라는 증거는 아닙니다.** 대면 안내 역시 담당 직원의 설명으로만 취급합니다. 현행 두 안내를 바탕으로 한모의 내부 정책을 정할 뿐 어느 쪽도 영구적인 '허용 목록'으로 확정하지 않습니다.

**변경 기록 최소 항목(설계, 미구현):** `scopePolicyVersion`, 안내 출처·종류(`staff_email`/`staff_oral_reported`/`institutional_policy_confirmed`), 수령·적용 검토 시각, 데이터 필드별 `allowed_candidate/blocked/needs_review`, 이전판 대비 확대/축소 차이, 검수·운영 판단, 수집/배포 판본 및 철회 조치. **공식 여부를 검증하지 않았다면 `institutional_policy_confirmed`를 사용하지 않습니다.**

**대안 및 채택 근거:** (A) 두 안내를 확정된 학교 정책으로 취급하면 검증되지 않은 권한을 단정하고 향후 범위 변경 때 대처하기 어렵기 때문에 **배제**. (B) 직원 안내의 구체적 금지·수집 조건을 현재 안전 경계로 지키되, 출처 지위와 확대/축소 가능성을 기록하는 **잠정 정책 + 필드별 버전관리 + 즉시 철회**를 채택합니다. 새 정보처 문의는 이번 변경의 필수 조건으로 설정하지 않습니다.

**제품 우선순위:** PC 전용 기능 차별화(공지 정밀 검색 [#53](https://github.com/ot4562-glitch/Hanmo_develop/issues/53), 과거 개설 분석 [#48](https://github.com/ot4562-glitch/Hanmo_develop/issues/48), 검수된 일정 달력 표시(후순위 P2) [#127](https://github.com/ot4562-glitch/Hanmo_develop/issues/127), 문의처 독립 학생 기능 **폐기** [#59](https://github.com/ot4562-glitch/Hanmo_develop/issues/59))이며 개인 메모·알림 중심 UX는 우선하지 않습니다. 검색의 포괄성은 학교의 엄격한 수집 한도에 따라 제한될 수 있습니다.

**2026-11-25 기능 우선순위 재확인:** PC 진단·반응속도 테스트·합성 전략 실험의 현행 구성 유지·안정화/신뢰성 검증은 두 협업자 공동 [#134](https://github.com/ot4562-glitch/Hanmo_develop/issues/134)에서 수행하며 학교 자료 사용 허가와 무관합니다. 실증 보정을 위한 학교 서버 접속·수강 관련 정보 수집이나 원격 텔레메트리 활성화는 승인된 개발 범위가 아닙니다.

## 3. 자동 수집 조건(서면 그대로 적용)

실제 학교 크롤러/스케줄러는 **미구현**, `data/academic-source-config.json`은 **`mode: disabled`**입니다. 이 의사결정은 설정 변경·실행 승인이나 수집 속도 상향을 뜻하지 않습니다.

- 로그인 없는 공개 화면에 보이는 URL만. 내부/비노출 API·SSO/계정·인증 우회 없음
- 학사공지 **1일 1회 이하, 첫 목록 페이지 및 신규 공지 상세만**; 강의시간표 **학기당 2회 이하**
- 요청 **10초 이상 간격**, 동시 **1개**, 실행당 **50건 이내**(여러 실행자/호스트 합산 관리)
- 수강신청·수강정정 기간 **전체 및 시작 전/종료 후 각 1일** 중단; 금지기간 전체를 확인하지 못하면 수집 시작 안 함
- 오류 응답/접속 제한 시 **당일 즉시 중단·재시도 금지**, User-Agent에 서비스명과 운영자 연락처 표기
- 학교 과부하·정책 변경·차단 시 수집과 해당 자료 공개 즉시 정지. 실제 구동은 [#66](https://github.com/ot4562-glitch/Hanmo_develop/issues/66) 합성/실환경 검증 및 [#126](https://github.com/ot4562-glitch/Hanmo_develop/issues/126) 긴급 철회 인수 뒤 별도 운영 판단

## 4. 중단 트리거

학교/권리자의 중단·삭제 요청, 정보 이용 조건 변경/철회, 오류·접속 제한·서버 부하, 개인정보나 서면 금지 필드 혼입, 허위/오래된 학사 정보, 출처 불일치·공식 서비스 오인 등이 확인되면 **우선 수집·해당 자료 노출을 차단**하고 원인 검토를 합니다. 학교 서버 오류가 난 날에는 다시 시도하지 않습니다.

## 5. 긴급 철회 런북 — '언제든 내리기'는 검증해야 함

1. **수집 중지:** 모든 스케줄/작업/요청 경로를 전역 OFF로 전환, 재시작·다중 인스턴스에서도 유지. 네트워크 경로 우회·오류 당일 재시도 없음
2. **학생 노출 중지:** 정적 스냅샷/JSON·Supabase 공개 뷰/API와 검색 인덱스에서 대상 자료 철회. 학생 화면은 `NOT_CONNECTED`/`INVALID`로 안전하게 전환. 단순히 설정 `mode: disabled`만 바꾸면 이미 배포된 파일은 남을 수 있음
3. **배포/캐시 정리:** GitHub Pages·다른 호스팅·이전 릴리스/아티팩트·CDN/브라우저 캐시·검색 엔진 색인·구형 백업/롤백 경로까지 확인. 급하면 해당 공개 호스팅을 우선 중지
4. **재노출 검사:** 익명 새 세션과 직접 파일 URL, 캐시/미리보기/이전판 및 Windows PC 브라우저에서 공개 자료가 사라졌는지 확인
5. **처리 기록:** 감지 시각(KST), 문제 출처/필드·공개 범위, 변경 SHA/배포 판본, 조치 담당·증거를 기록하되 원문/개인정보/학교 직원 신원 등은 불필요하게 남기지 않음
6. **재개 별도 심사:** 철회된 판본의 자동 복원·구형 빌드 롤백 금지. 운영자+독립 검수자가 필드·출처·수집 예산·정책과 기술적 재노출 방지를 확인한 경우에만 재개 여부 결정

**현재 공개 QA 경계.** 정적 빌드는 `mode: disabled` 설정과 검증된 합성 네트워크 파일만 `data/`에 넣습니다. 활성 설정이나 이전 스냅샷이 산출물에 있으면 배포 사전 검사를 통과할 수 없습니다. Pages는 `main`의 빌드만 허용하고, 배포 직전에 후보 SHA가 원격 `main`과 일치하는지 확인합니다. 긴급 철회 때는 구판 워크플로 재실행으로 복구하지 말고, 자료가 빠진 현재 `main`에서 새로 빌드합니다.

**정적 철회 훈련.** `npm run build` 후 `node --test tests/preview-withdrawal.test.mjs`를 실행합니다. 이 검사는 격리된 디렉터리와 로컬 서버에서 합성 구판의 기존 직접 URL로 200 응답을 확인합니다. 같은 배포 패키징 스크립트로 재빌드한 후 직전 URL과 쿼리 문자열을 붙인 URL이 모두 404인지, 학사자료 설정이 계속 비활성인지, 모의연습 페이지가 열리는지 검사합니다. 빌드 원본에 구판 사본을 남겨도 공개 산출물에 다시 포함되면 실패합니다. 활성 설정의 복원을 시도하면 패키징이 중단되고 마지막 비활성 산출물이 유지되는지도 확인합니다. 원격 호스팅과 CDN, 운영 DB는 건드리지 않습니다.
